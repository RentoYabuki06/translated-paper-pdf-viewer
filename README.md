# 翻訳論文 PDF ビューア

英語の論文 PDF を、ページのレイアウトを保ったまま日本語で読むための、ブラウザで動くアプリです。
元のページの上に、段落ごとの訳文を同じ位置に重ねて表示します。
翻訳には、Preferred Networks(以下 PFN)が公開している翻訳専用の言語モデル **PLaMo 3 Translate** を使います[PFN モデルカード (2026/11), 冒頭]。
モデルは自分のパソコンの上で動かすため、論文の本文を外部の翻訳サービスへ送りません。

対象にする PDF は、arXiv(論文を公開するサイト)で配布されるものや出版社版のように、文字の情報を持つものです。
紙をスキャンした画像だけの PDF は対象にしません。

このアプリは開発の途中です。
論文の PDF を開いて、日本語で読むところまで動きます。
ただし、次の制限があります。

- 訳文は、段落ごとに独立して訳されます。参考として、論文の題名、節の見出し、直前の段落を翻訳のモデルに渡していますが、訳語が段落によって変わることがあります。訳語をそろえたい語は、用語集に登録できます。ただし、訳語の指定は、必ず守られるとは限りません(「用語集」の節)。

いまの画面でできることは、次の 4 つです。

- PDF を開き、訳す段落を自動で選んで翻訳し、訳文を元の段落の位置に重ねて読むこと。文中の数式は、元の見た目のまま訳文に入ります。段やページをまたいで続く段落は、1 つにつないで訳します
- PDF から読み取った段落、行、文中の数式、検出した領域の範囲を、枠で確かめること
- 英語の文章を貼り付けて、段落ごとの訳文を確かめること
- 訳語を指定したい語を、用語集に登録すること

文中の角括弧は出典を示し、一覧は末尾の「出典」にあります。
出典の「モデルカード」は、モデルの配布ページに PFN が載せている説明書きです。

## 仕組み

次の 2 つを、同じパソコンの上で動かします。

| 部品 | 役割 |
| --- | --- |
| Web アプリ | ブラウザの中で動き、PDF の描画、段落の検出、訳文の重ね表示、訳文の保存を受け持ちます。貼り付けた英文の訳文も表示します |
| llama-server | PLaMo 3 Translate を読み込み、翻訳を受け持ちます |

**llama-server** は、言語モデルを動かすソフト **llama.cpp** に付属する HTTP サーバーです[llama.cpp 1.0.0 (2026/11), tools/server/README.md]。
Web アプリは、llama-server(既定では `http://127.0.0.1:8080`)へ原文を送り、訳文を受け取る作りです。
文章を貼り付けて訳す画面は、貼り付けられた英文を段落に分け、この通信で 1 段落ずつ訳文を受け取ります。
llama-server の代わりに、Ollama(言語モデルを動かす別のソフト)へ依頼する設定もあります(「翻訳サーバーの設定」の節)。

PDF の描画と、文字の位置の読み取りには、Mozilla の **PDF.js** を使います[PDF.js 6.5.438 (2026/11), README.md]。
PDF の解釈もブラウザの中で行うため、開いた PDF はどこにも送りません。

図や表の中の文字と本文を区別するために、レイアウト検出モデル **PP-DocLayoutV3** を使います[PP-DocLayoutV3 (2026/6), README.md]。
レイアウト検出モデルは、ページの画像から、本文、図、表、数式などの領域を推定する機械学習モデルです。
このモデルも、**ONNX Runtime Web** を使ってブラウザの中で動かします[ONNX Runtime Web 1.31.1 (2026/11), パッケージの説明]。

llama-server は、コマンド `npm run model` で起動します。
このコマンドは、モデルの指定と、PLaMo 3 Translate に必要なオプションを付けて llama-server を起動します。
オプションの内容と理由は [note/004_llama-launcher.md](note/004_llama-launcher.md) に書いています。

## セットアップ

手順 1 と手順 2 で、Web アプリを表示できます。
手順 3 と手順 4 は、PLaMo 3 Translate を実際に動かすための準備です。
手順 5 で、ブラウザから翻訳を試します。
llama.cpp を導入せずに実験用のコマンドを試す方法は、「動作の確認」に書いています。

### 1. リポジトリを取得して、依存パッケージを入れる

```bash
git clone https://github.com/RentoYabuki06/translated-paper-pdf-viewer.git
cd translated-paper-pdf-viewer
npm install
```

このリポジトリは、2026 年 11 月の時点で非公開です。
取得するには、閲覧を許可された GitHub のアカウントでの認証が必要です。

`npm install` が終わると、`added 68 packages` のように、取得したパッケージの数が表示されます。
途中で `npm warn install-scripts` で始まる警告が出ることがあります。
この警告が出ても、そのまま次の手順へ進めます。

### 2. Web アプリを起動する

```bash
npm run dev
```

表示された URL(既定では `http://localhost:5173/`)を Chrome で開きます。
「PDF を開く」「文章を貼り付けて訳す」「用語集」「翻訳サーバー」の 4 つのボタンがあるページが表示されれば、ここまでの手順は成功です。
ページの右上には、翻訳サーバーとの接続の状態が表示されます。llama-server をまだ起動していないので、この時点では `接続できません` と表示されます。
PDF の表示と解析結果の確認は、ここまでの手順だけで使えます(「PDF を開く」の節)。
PDF の翻訳には、手順 3 と手順 4 も必要です。
止めるときは、ターミナルで Ctrl+C を押します。

### 3. llama.cpp を導入する

macOS では、Homebrew で導入できます。

```bash
brew install llama.cpp
```

ほかの OS での導入の方法は、[llama.cpp の配布ページ](https://github.com/ggml-org/llama.cpp)を見てください。

導入できたかどうかは、次のコマンドで確かめます。
版の情報が表示されれば、導入できています。

```bash
llama-server --version
```

Homebrew で導入できる版は、2026 年 11 月 14 日の時点で 1.0.0 です[Homebrew (2026/11), llama.cpp]。
1.0.0 と 0.9.0 のソースコードには、PLaMo 3 を読み込む処理が含まれています[llama.cpp 1.0.0 (2026/11), src/models/plamo3.cpp]、[llama.cpp 0.9.0 (2026/11), src/models/plamo3.cpp]。
手順 4 のコマンドが渡すオプションも、1.0.0 のソースコードに含まれています[llama.cpp 1.0.0 (2026/11), common/arg.cpp]。
実際に動かして確かめた版は 1.0.0 だけです。
0.9.0 より古い版は調べていないので、その場合は更新してから進めてください。
Homebrew で導入した llama.cpp は、`brew upgrade llama.cpp` で更新できます。

### 4. llama-server を起動する

```bash
npm run model
```

このコマンドは、既定のモデル(`2b`)を読み込んだ llama-server を起動します。
npm 自身の表示に続いて、次の 2 行が表示されます。
2 行目は、ここでは途中を省略しています。

```text
モデルの情報を読んでいます: https://huggingface.co/pfnet/plamo-3-translate-2b-GGUF/resolve/main/plamo-3-translate-2b-Q4_K_M.gguf
llama-server -hf pfnet/plamo-3-translate-2b-GGUF:Q4_K_M --alias plamo-3-translate-2b-Q4_K_M ...
```

1 行目は、モデルの情報を Hugging Face(機械学習のモデルを配布するサイト)から読んでいることを示します。
2 行目は、これから実行する llama-server のコマンドです。
そのあとに、llama-server 自身の表示が続きます。

初回は、llama-server がモデルのファイルを Hugging Face から取得します[llama.cpp 1.0.0 (2026/11), common/arg.cpp]。
ファイルの大きさは 1.81 GB です[PFN モデルカード (2026/11), Usage]。
取得したファイルは、このリポジトリの中ではなく、llama.cpp の既定の場所である `~/.cache/huggingface/hub` に保存されます[llama.cpp 1.0.0 (2026/11), common/hf-cache.cpp]。

モデルの利用には、PLaMo コミュニティライセンス契約が適用されます[PLaMo コミュニティライセンス (2026/11), 前文]。
条件の概要は「ライセンス」に書いています。

準備ができたかどうかは、別のターミナルで次のコマンドを実行して確かめます。

```bash
curl http://127.0.0.1:8080/health
```

llama.cpp の説明書によると、モデルの読み込みが終わっていれば `"status": "ok"` を含む応答が返り、読み込みの途中であれば状態コード 503 のエラーが返ります[llama.cpp 1.0.0 (2026/11), tools/server/README.md]。

起動したあとは、`npm run model` を実行したターミナルを開いたままにします。
llama-server は `http://127.0.0.1:8080` で依頼を待ち受け、同じパソコンからの接続だけを受け付けます。
止めるときは、そのターミナルで Ctrl+C を押します。

`npm run model` は、起動のたびにモデルの情報を Hugging Face から読みます。
そのため、2 回目以降の起動にもインターネット接続が必要です。

llama.cpp を導入する前に、実行されるコマンドだけを見たい場合は、`npm run model -- --dry-run` を使います。
`npm run` のコマンドに指定を渡すときは、このように `--` のあとに書きます。

### 5. ブラウザで翻訳する

手順 2 の Web アプリと、手順 4 の llama-server の両方を起動した状態で、Web アプリのページを開きます。

まず、llama-server に接続できていることを確かめます。
ページの右上に、接続の状態が表示されます。
`接続済み: plamo-3-translate-2b-Q4_K_M` と表示されていれば、接続できています。
表示の後ろの部分は、llama-server が知らせるモデルの名前で、モデルの大きさ(`2b`)と量子化の種類(`Q4_K_M`)を含みます。
`接続できません` と表示されている場合は、「翻訳サーバー」を押して、設定を確かめます(「翻訳サーバーの設定」の節)。

次に、「文章を貼り付けて訳す」を押します。

1. 「英語の原文」の欄に英語の文章を貼り付けます。空行が段落の区切りになります。
2. 「翻訳する」を押します。段落ごとに、原文の右に訳文が表示されます。

この画面の訳文は保存されず、ページを読み込み直すと消えます。
1 段落の訳文の長さには上限(1,024 トークン)があり、上限に達した段落には、訳文が途中で切れたことが表示されます。

## 翻訳サーバーの設定

Web アプリの「翻訳サーバー」の画面で、翻訳を依頼するソフトと、その URL を設定します。
設定は、ブラウザに保存されます。
ページの右上には、いまの依頼先と接続の状態が、いつも表示されます。押すと、この画面に切り替わります。

| 項目 | 内容 |
| --- | --- |
| 翻訳を依頼するソフト | llama-server か、Ollama を選びます。既定は llama-server です |
| llama-server の URL | 既定は `http://127.0.0.1:8080` です。llama-server を別のポート番号で起動した場合は、その番号に書き換えます |
| 接続を確かめる | 依頼先に接続し、モデルの名前、同時に処理できる依頼の数、1 件の依頼で使える長さを表示します |

接続の確認は、ページを開いたときと、翻訳を始めるときにも、自動で行われます。
接続できなかった場合は、理由と、確かめる点が表示されます。
接続はできたものの、気を付ける点がある場合(モデルの名前に `plamo` が含まれない場合など)は、注意が表示されます。

### Ollama を使う場合

Ollama は、言語モデルを動かす別のソフトです。
すでに Ollama を使っている場合は、llama-server の代わりに、Ollama に翻訳を依頼できます。
ただし、このアプリが主に対応している依頼先は、llama-server です。
Ollama では、一部の段落の訳文が llama-server のものと変わり、PDF の翻訳にかかる時間も長くなります(下の「llama-server との違い」)。

#### モデルを Ollama に入れる

Ollama は、手元にあるモデルのファイルを取り込めます[Ollama 説明書 (2026/11), import, Importing a GGUF model]。
「セットアップ」の手順 4 で llama-server が取得したファイルを取り込む場合は、次の 2 つのコマンドを実行します。

```bash
echo "FROM $(ls ~/.cache/huggingface/hub/models--pfnet--plamo-3-translate-2b-GGUF/snapshots/*/plamo-3-translate-2b-Q4_K_M.gguf)" > Modelfile
ollama create plamo-3-translate-2b -f Modelfile
```

1 つ目のコマンドは、モデルのファイルの場所を書いたファイル(Modelfile)を、いまのディレクトリに作ります。
2 つ目のコマンドは、そのファイルを Ollama に取り込み、`plamo-3-translate-2b` という名前を付けます。
最後に `success` と表示され、`ollama list` の表示に `plamo-3-translate-2b` があれば、取り込めています。
Ollama の保存場所(`~/.ollama/models`)には、モデルのファイルと同じ大きさ(1.81 GB)のファイルが作られます。
取り込んだモデルは、`ollama rm plamo-3-translate-2b` で消せます[Ollama 説明書 (2026/11), cli, Remove a model]。

#### アプリの設定

「翻訳を依頼するソフト」で Ollama を選ぶと、次の項目が表示されます。

| 項目 | 内容 |
| --- | --- |
| Ollama の URL | 既定は `http://127.0.0.1:11434` です |
| モデルの名前 | Ollama に入れた PLaMo 3 Translate のモデルの名前です。上の手順で入れた場合は、`plamo-3-translate-2b` です。「接続を確かめる」を押すと、Ollama に入っているモデルの名前が、候補として表示されます |
| 同時に依頼する数 | Ollama は、同時に処理できる依頼の数を知らせないため、ここで指定します。既定は 1 です |

「接続を確かめる」を押して `接続できました` と表示されれば、llama-server のときと同じ操作で翻訳できます。

#### llama-server との違い

開発に使っているパソコン(Apple M5、Ollama 0.40.16、モデルは `2b`・Q4_K_M)で確かめた結果は、次のとおりです。
詳しい記録は [note/021_probe-backends.md](note/021_probe-backends.md) と [note/022_ollama-plamo-check.md](note/022_ollama-plamo-check.md) にあります。

**一部の段落で、訳文が変わります。**
`npm run model` は、llama-server の起動時に、PLaMo 3 Translate 向けの補正の値を渡しています([note/004_llama-launcher.md](note/004_llama-launcher.md))。
Ollama には、この値を渡す手段が見つかっていません。
同じ文章を両方に訳させると、短い入力では同じ訳文になり、長い入力では訳文が変わることがありました。
補正の値を渡さずに起動した llama-server は、確かめた 4 通りの入力すべてで、Ollama と一字一句同じ訳文を返しました。
arXiv 1706.03762 では、104 段落のうち 99 段落が llama-server と同じ訳文になり、5 段落は言い回しが変わりました(「英仏翻訳」と「英語-フランス語翻訳」など)。
どちらの訳文が良いかは、評価していません。
この比較は、`npm run probe:backends -- --llama http://127.0.0.1:8080 --ollama-model plamo-3-translate-2b` でやり直せます。

**PDF の翻訳にかかる時間が、長くなります。**
Ollama は、既定では、1 つのモデルで依頼を 1 件ずつ処理します[Ollama 説明書 (2026/11), faq, How does Ollama handle concurrent requests?]。
`npm run model` で起動した llama-server は、4 件を同時に処理します。

| 論文 | 訳した段落 | 失敗 | Ollama での時間(秒) | llama-server での時間(秒) |
| --- | ---: | ---: | ---: | ---: |
| arXiv 1706.03762(1 段組) | 104 | 0 | 107.6 | 45.2 |
| arXiv 1512.03385(2 段組) | 132 | 0 | 192.2 | 75.7 |

時間は、「この PDF を翻訳する」を押してから、すべての段落を訳し終えるまでのもので、測定はそれぞれ 1 回です。
llama-server での時間は、「PDF を翻訳する」の節に書いた値です。
Ollama での測定では、「同時に依頼する数」を、1706.03762 では 1、1512.03385 では 4 にしました。

依頼を 1 件ずつ送ったときの生成の速度は、どちらも 61 から 67 トークン毎秒で、差はありませんでした。
「同時に依頼する数」を増やしても、Ollama の側が 1 件ずつ処理するため、速くはなりません。
段落 8 件を訳す時間は、1 件ずつ送った場合が 11.4 秒、同時に 4 件送った場合が 10.9 秒でした。
Ollama の側で同時に処理する数(環境変数 `OLLAMA_NUM_PARALLEL`)を増やした場合は、確かめていません。

**しばらく使わなかったあとの最初の依頼に、時間がかかります。**
Ollama は、既定では、モデルをメモリに 5 分間保ったあとで降ろします[Ollama 説明書 (2026/11), faq, How do I keep a model loaded in memory or make it unload immediately?]。
モデルの読み込みが入った依頼は、そうでない依頼より、2 秒から 7 秒ほど長くかかりました。

## PDF を開く

Web アプリの「PDF を開く」の画面で、PDF を開けます。
表示と解析結果の確認だけなら、llama-server は要りません。
翻訳するには、llama-server を起動しておきます(「セットアップ」の手順 4)。
開き方は 3 通りあります。

- 「PDF のファイルを選ぶ」を押して、ファイルを選びます。
- 画面へ PDF のファイルをドラッグ&ドロップします。
- arXiv の ID(例: `1706.03762`)または URL を入力して、「arXiv から開く」を押します。この場合は、ブラウザが arXiv から PDF を取得します。

`http://localhost:5173/?arxiv=1706.03762` のように、URL に `?arxiv=` と ID を付けて開くこともできます。

PDF を開くと、ページが上から順に並びます。
ページの上には、PDF から読み取った結果が枠で重なります。
枠の種類は、ページの上のチェックボックスで切り替えます。

| チェックボックス | 表示されるもの |
| --- | --- |
| 段落 | 段落と判定した範囲(青い枠)。枠にマウスを重ねると、読み取った文章が表示されます |
| 行 | 行と判定した範囲(緑の枠) |
| 文字のまとまり | 同じフォントで続けて書かれた文字のまとまり(灰色の枠)。マウスを重ねると、文字とフォントの名前が表示されます |
| 文中の数式 | 文中の数式と判定した範囲(橙色の塗り)。マウスを重ねると、読み取った文字が表示されます |
| 文字を描かない描画を見る | 文字を描く命令を飛ばして描画したページ。訳文を重ねるときに、元の文字を消すために使っている描画です。翻訳を始めたあとは、訳す段落の中の細い罫線(分数の線など)も描かれません |

この表示は、段落の検出や数式の検出が正しいかを目で確かめるためのものです。
検出の方法と、分かっている誤りは、[note/009_pdf-view.md](note/009_pdf-view.md) と [note/012_inline-math.md](note/012_inline-math.md) に書いています。

### レイアウト検出

PDF を開いたあと、「レイアウト検出」の「有効にする」を押すと、表示したページから順に領域を検出します。
初回は、検出モデルのファイル(130.5 MB)を Hugging Face から取得するため、時間がかかります。
取得の進み具合は、ボタンの右に表示されます。

検出が終わったページでは、表示が次のように変わります。

| 表示 | 意味 |
| --- | --- |
| 紫の枠と名前 | 検出した領域。名前は、読む順番を表す数値、領域の種類、確からしさ(0 から 1)の順です。「検出した領域」のチェックボックスで切り替えます |
| 青い実線の段落の枠 | 訳す段落。本文、要旨、題名、節の見出し、図表の説明文、脚注に当たります |
| 灰色の破線の段落の枠 | 訳さない段落。図や表の中の文字、独立した数式、参考文献、ページ番号などと、どの領域にも当たらなかった段落です |

段落の枠にマウスを重ねると、割り当てた種類が表示されます。
ボタンの右には、検出にかかった時間が表示されます。

「実行の方法」では、WebGPU と WebAssembly を選べます。
開発に使っているパソコン(Apple M5)で測った 1 ページあたりの時間は、次のとおりです。
測定の条件は [note/010_layout-detection.md](note/010_layout-detection.md) に書いています。

| 実行の方法 | 中央値(ミリ秒) | 最大(ミリ秒) |
| --- | ---: | ---: |
| WebGPU | 257 | 442 |
| WebAssembly(8 スレッド) | 951 | 1,077 |

WebAssembly を複数のスレッドで動かすには、Web アプリを配るサーバーが 2 つの応答ヘッダー(`Cross-Origin-Opener-Policy` と `Cross-Origin-Embedder-Policy`)を返す必要があります。
`npm run dev` と `npm run preview` は、このヘッダーを返します。
`dist/` の内容を別のサーバーで配る場合は、そのサーバーで同じヘッダーを設定します。

### PDF を翻訳する

1. llama-server を起動します(「セットアップ」の手順 4)。
2. ページの右上の表示が `接続済み` になっていることを確かめます。なっていない場合は、「翻訳サーバー」の画面で設定を確かめます(「翻訳サーバーの設定」の節)。
3. PDF を開きます。
4. 「この PDF を翻訳する」を押します。

レイアウト検出が有効になっていない場合は、このときに自動で有効になります。
初回は、検出モデルのファイル(130.5 MB)の取得が入ります。

翻訳は、表示しているページから始まり、後ろのページへ進みます。
訳し終えた段落から順に、元の段落の位置に訳文が表示されます。
翻訳している最中の段落は、薄い青で点滅します。
進み具合は、ボタンの下に表示されます。

| 操作 | 内容 |
| --- | --- |
| 訳文をクリック | その段落を原文の表示に戻します。もう一度クリックすると、訳文に戻ります。段やページをまたぐ段落は、すべての範囲がまとめて切り替わります |
| 「訳文を表示」のチェックボックス | すべての段落の訳文を、まとめて表示または非表示にします |
| 「中止」 | 翻訳の依頼を止めます。訳し終えた段落は、そのまま残ります。進み具合には「翻訳を中止しました」と表示されます。もう一度「この PDF を翻訳する」を押すと、残りの段落を訳します |

訳す段落は、レイアウト検出の結果で決まります。
訳すのは、本文、要旨、題名、節の見出し、図表の説明文、脚注です。
図や表の中の文字、独立した数式、参考文献、ページ番号、著者の欄は、原文のまま残ります。

文中の数式は、訳しません。
翻訳の前に、原文の中の数式を番号の付いた目印(`<m1>` など)に置き換え、訳文の目印の位置に、元のページから切り抜いた数式を置きます。
数式を組み直さないので、分数、根号、添字などの見た目は、原文と同じになります。
数式にマウスを重ねると、PDF から読み取った数式の文字が表示されます。

翻訳のモデルには、段落の原文のほかに、参考になる文章(文脈)を渡します。
本文の段落には、論文の題名、節の見出し、直前の段落を渡します。
節の見出しには、題名と、その節の最初の段落を渡します。
文脈は訳されず、訳語を選ぶ手がかりとして使われます。
節の見出しの番号("3.2" など)は、訳さずに、訳文の前にそのまま付けます。

段の下端で文の途中のまま終わり、次の段(または次のページ)の上端から続く段落は、1 つにつないで訳します。
訳文は、もとの 2 つの範囲へ、前から順に流し込みます。
訳文が原文より短い場合は、後ろの範囲が空くことがあります。

訳文の中の目印がそろわなかった段落(目印が欠けた、または重複した段落)は、文ごとに分けて訳し直します。
それでもそろわない段落は、原文のまま残し、橙色の破線の枠を付けます。

訳文は、元の段落の範囲に収まるように、文字の大きさと行送りを調整します。
収まらない場合は、下の空きへ広げ、行送りを詰め、文字を元の 67% まで小さくします。
それでも収まらない訳文は、末尾を隠して右下に「…」の印を付けます。マウスを重ねると、全文が表示されます。

訳文は、ブラウザに保存されます。
同じ PDF を同じモデルで開き直して「この PDF を翻訳する」を押すと、保存した訳文が使われ、翻訳サーバーへの依頼は行われません。
保存した訳文は、モデルの名前ごとに分かれます。llama-server と Ollama では、同じモデルでも名前が違うため、保存した訳文は共有されません。
`npm run model` で起動した llama-server の名前は、モデルの大きさと量子化の種類を含みます(「モデルの大きさと起動時の指定」の節)。そのため、モデルの大きさを替えた場合も、訳文は分けて保存されます。
翻訳したあとで依頼先を切り替えて、もう一度「この PDF を翻訳する」を押すと、切り替えた先の訳文に入れ替わります。
用語集を変えた場合は、訳語の指定が変わる段落だけが訳し直されます(「用語集」の節)。
保存した訳文を消す操作は、まだありません。消す場合は、ブラウザの設定で、このサイトのデータを削除します。

開発に使っているパソコン(Apple M5、モデルは `2b`・Q4_K_M、依頼先は llama-server)で確かめた結果は、次のとおりです。

| 論文 | ページ数 | 訳した段落 | うち、つないだ段落 | 失敗 | 目印がそろわず原文のまま | 収まらなかった訳文 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| arXiv 1706.03762(1 段組) | 15 | 104 | 5 | 0 | 0 | 0 |
| arXiv 1512.03385(2 段組) | 12 | 132 | 14 | 0 | 0 | 0 |

翻訳にかかる時間は、1706.03762 で 45.2 秒(依頼 103 件)、1512.03385 で 75.7 秒(依頼 130 件)でした。
ボタンを押してから、すべての段落を訳し終えるまでの時間で、レイアウト検出の時間を含みます。測定はそれぞれ 1 回です。

この 2 本は、どちらも本文のフォントが Times 系です。
本文が Computer Modern の論文(arXiv 1011.3027、61 ページ)では、途中の 1 ページを開いて翻訳し、文中の数式の表示を確かめました。全ページの翻訳は行っていません。

詳しい記録は [note/011_pdf-translation.md](note/011_pdf-translation.md)、[note/012_inline-math.md](note/012_inline-math.md)、[note/013_inline-math-cm-body.md](note/013_inline-math-cm-body.md)、[note/015_paragraph-chains.md](note/015_paragraph-chains.md)、[note/017_translation-context.md](note/017_translation-context.md) にあります。

## 用語集

訳語をそろえたい語は、Web アプリの「用語集」の画面で登録できます。
PLaMo 3 Translate の入力には、原文の語と訳語の組を渡す欄(用語集)があります[PFN モデルカード (2026/11), Specifying terms with a glossary]。
このアプリは、登録した組をその欄に入れて、翻訳を依頼します。
用語集は、ブラウザに保存されます。

| 操作 | 内容 |
| --- | --- |
| 追加 | 「原文の語」と「訳語」を入力して、「追加」を押します。同じ語が登録済みの場合は、追加されません |
| 書き換え | 一覧の入力欄を、直接書き換えます。語か訳語が空の行と、上の行と同じ語の行は、翻訳に使われません。その場合は、理由が行の下に表示されます |
| 削除 | 行の右の「削除」を押します |

登録できるのは 500 行までで、語と訳語の長さは、それぞれ 100 文字までです。
訳語に、原文と同じ語を書くと、その語を英語のまま残せます。

### 訳語の指定が付く段落

訳語の指定は、登録した語が出てくる段落の依頼にだけ付きます。
PDF の翻訳と、貼り付けた英文の翻訳の、両方で使われます。
語が出てくるかどうかは、次の決まりで判定します。

- 大文字と小文字は、区別しません。ただし、2 文字目以降に大文字がある語(`RNN`、`CLIP` など)は、略語とみなして、大文字と小文字が同じ場合にだけ当てはめます。
- 複数形(語尾に s か es が付いた形と、語尾の y が ies に変わった形)にも当てはめます。動詞の活用形と、形が不規則に変わる複数形には、当てはめません。
- 語と語の間の空白とハイフンは、区別しません(`self attention` は `self-attention` に当てはまります)。
- 別の語の一部には、当てはめません(`net` は `network` に当てはまりません)。
- 長い語と、その一部である短い語の両方を登録してある場合(`self-attention` と `attention`)、短い語が長い語の一部としてしか出てこない段落には、長い語の指定だけを付けます。
- 1 件の依頼に付ける指定は、30 件までです。

PDF の訳文にマウスを重ねると、その段落に付けた指定が表示されます。
「文章を貼り付けて訳す」の画面では、訳文の下に表示されます。

### 用語集を変えたあとの訳し直し

用語集を変えたあとで、「この PDF を翻訳する」をもう一度押すと、訳語の指定が変わる段落だけを訳し直します。
指定が変わらない段落は、依頼をせずに、いまの訳文をそのまま使います。
用語集を変えると、「PDF を開く」の画面に、訳し直しを案内する文が表示されます。

arXiv 1706.03762(104 段落)では、次のようになりました。

| 操作 | 依頼した段落 | 依頼しなかった段落 | 時間(秒) |
| --- | ---: | ---: | ---: |
| `attention` と `residual connection` を登録して翻訳 | 46 | 58 | 25.6 |
| `encoder` を足して、もう一度翻訳 | 18 | 86 | 9.1 |
| 用語集を空にして、もう一度翻訳 | 0 | 104 | 0.2 |

1 行目の時間は、PDF を開いた直後に測ったもので、レイアウト検出の時間を含みます。測定はそれぞれ 1 回です。

### 確かめた結果と、気を付ける点

開発に使っているパソコン(Apple M5、モデルは `2b`・Q4_K_M、依頼先は llama-server)で確かめた結果は、次のとおりです。
詳しい記録は [note/023_probe-glossary.md](note/023_probe-glossary.md) と [note/024_glossary.md](note/024_glossary.md) にあります。

**訳語の指定は、必ず守られるとは限りません。**
短い文章 40 件に、原文に出てくる語の訳語を指定して訳させると、36 件が指定どおりになりました(`npm run probe:glossary`)。
指定どおりにならなかった 4 件のうち 3 件は、略語を日本語の名前に置き換える指定(`RNN` に「再帰型ニューラルネットワーク」など)でした。
残りの 1 件は、複合語の一部になっている語(`self-attention` と `encoder-decoder attention` の中の `attention`)でした。

実際の論文 2 本では、次のようになりました。
数は、登録した語が出てくる段落のうち、訳文にその訳語を含む段落の数です。
arXiv 1512.03385 の数は、用語集を付けずに訳し直した 1 段落(下で説明します)を除いたものです。

| 論文 | 登録した語と訳語 | 語が出てくる段落 | 用語集なしで訳語を含む段落 | 用語集ありで訳語を含む段落 |
| --- | --- | ---: | ---: | ---: |
| arXiv 1706.03762 | `attention` に「注意」 | 46 | 8 | 45 |
| arXiv 1706.03762 | `residual connection` に「スキップ接続」 | 2 | 0 | 2 |
| arXiv 1706.03762 | `encoder` に「符号化器」 | 18 | 0 | 10 |
| arXiv 1512.03385 | `shortcut connection` に「近道接続」 | 8 | 0 | 8 |
| arXiv 1512.03385 | `degradation` に「性能低下」 | 12 | 6 | 12 |
| arXiv 1512.03385 | `layer` に「レイヤー」 | 52 | 0 | 22 |

- 用語集が無い場合、`attention` は、40 段落で「アテンション」、8 段落で「注意」と訳されていました(2 段落は、両方を含みます)。用語集を付けると、「アテンション」が残る段落は 3 段落になりました。残ったのは、「セルフアテンション」「マルチヘッドアテンション」などの複合語です。
- `degradation` も、用語集が無い場合は「性能低下」と「劣化」に分かれていました。用語集を付けると、12 段落すべてが「性能低下」になりました。
- `encoder` と `layer` は、指定が効かない段落が多く残りました。`encoder` は、「エンコーダ・デコーダ」のような複合語を含む段落で、もとの訳語のままになることがありました。`layer` は、「152層」のように数に続く場合に、「層」のままになりました(「層」が残った 128 か所のうち 70 か所)。
- 指定した訳語に、別の語が足されることがあります。`attention` に「注意」を指定した訳文では、83 か所のうち 19 か所が「注意機構」でした。
- 表の訳語は、効いたかどうかを見分けやすいように選んだもので、訳語として薦めるものではありません。

**用語集を付けると、数式の目印がそろわなくなる段落が出ることがあります。**
用語集を付けると、訳語のほかの部分の言い回しも変わります。
arXiv 1512.03385 では、語が出てくる 60 段落のうち 1 段落で、用語集を付けたときにだけ、訳文から数式の目印が 1 つ欠けました。
このような段落は、用語集を付けずに訳し直します。
訳し直した段落には、訳語の指定が反映されません。訳文にマウスを重ねると、その旨が表示されます。
arXiv 1706.03762 では、このような段落はありませんでした。

**Ollama でも、用語集は同じように効きます。**
短い文章 44 件(原文に出てこない語を渡した 4 件を含みます)に用語集を付けた訳文は、llama-server と Ollama で一字一句同じでした。
Ollama に依頼して、用語集を付けた PDF を翻訳する操作は、確かめていません。

## 動作の確認

### 単体テストとビルド

```bash
npm test
npm run build
```

どちらもエラーなく終われば、手順 1 は正しく完了しています。

### llama.cpp を導入せずに試す方法

模擬サーバーを使うと、llama.cpp が無くても、実験用のコマンドの流れを試せます。
模擬サーバーは翻訳を行わず、原文の先頭に「【訳】」を付けて返します。

1 つ目のターミナルで、模擬サーバーを起動します。

```bash
npm run mock
```

`模擬サーバーを起動しました: http://127.0.0.1:8089(同時処理数 4)` と表示されれば、起動できています。

2 つ目のターミナルで、依頼先を模擬サーバーに変えて、生成の速度を測るコマンドを実行します。

```bash
npm run probe:speed -- --base-url http://127.0.0.1:8089
```

このコマンドは、英語の段落 20 件を、同時に依頼する数を 1、2、4 と変えながら 3 回訳させます。
10 秒ほどで、同時に依頼する数ごとの速度の表と、訳文の例が表示されます。
速度の単位はトークン毎秒で、トークンは、モデルが文章を扱う単位です。
模擬サーバーの場合、表示される速度は見かけの値で、実物の性能とは関係がありません。

`npm run probe:placeholders`、`npm run probe:context`、`npm run probe:glossary` も、同じ `--base-url` の指定で模擬サーバーに対して実行できます。
`npm run probe:backends` は、比べる依頼先を `--llama` で 2 つ以上指定します。
模擬サーバーで流れを試す場合は、`npm run probe:backends -- --llama http://127.0.0.1:8089 --llama http://127.0.0.1:8089` のように、同じ URL を 2 回指定します。

### 実物の llama-server への依頼

手順 4 で llama-server を起動した状態で、別のターミナルから次を実行します。

```bash
npm run probe:speed
```

速度の表が表示されれば、llama-server への依頼は成功しています。
開発に使っているパソコン(Apple M5、メモリ 24 GB)で、既定のモデル(`2b`、Q4_K_M)に対して測った結果は次のとおりです。
英語の段落 20 件(合計 1,391 語)を訳させ、生成されたトークンは 2,159 でした。

| 同時に依頼する数 | 時間(秒) | 全体の速度(トークン毎秒) |
| ---: | ---: | ---: |
| 1 | 33.0 | 65.4 |
| 2 | 24.6 | 87.6 |
| 4 | 12.4 | 173.8 |

この表の測定は、1 回です。
別の日に同じ手順で測り直した値は、64.7、86.4、171.8 トークン毎秒でした(「モデルの大きさと起動時の指定」の節)。
詳しい結果は [note/008_paste-translate-screen.md](note/008_paste-translate-screen.md) に書いています。

## モデルの大きさと起動時の指定

`npm run model` は、1 つ目の引数でモデルの大きさを選べます。

```bash
npm run model -- 8b
```

PFN は、PLaMo 3 Translate を 4 種類の大きさで公開しています[PFN モデルカード (2026/11), Model List]。
`2b` などは、その大きさの呼び名です。

| モデルの大きさ | ファイルの大きさ | 評価値(PFTB) |
| --- | ---: | ---: |
| `0.8b` | 0.57 GB | 0.5832 |
| `2b`(既定) | 1.81 GB | 0.6062 |
| `8b` | 5.28 GB | 0.6100 |
| `31b` | 19.53 GB | 0.6237 |

表の値は、既定の量子化の種類(Q4_K_M)でのものです[PFN モデルカード (2026/11), Accuracy changes from quantization]。
**量子化**は、モデルの数値を少ないビット数で表して、ファイルを小さくする処理です。
PFTB は、同じモデルカードに載っている英日と日英の翻訳の評価値で、高いほど良い値です。

開発に使っているパソコン(Apple M5、メモリ 24 GB)で、`0.8b`、`2b`、`8b` を同じ手順で測った結果は、次のとおりです。
どれも、`npm run model` と同じ指定(同時に処理する数 4)で起動しました。
測定は、それぞれ 1 回です。詳しい記録は [note/027_model-sizes.md](note/027_model-sizes.md) にあります。

| モデルの大きさ | 生成の速度(依頼 1 件ずつ) | 生成の速度(同時に 4 件) | メモリの使用量 | 論文 1 本の翻訳時間 |
| --- | ---: | ---: | ---: | ---: |
| `0.8b` | 196.5 トークン毎秒 | 513.1 トークン毎秒 | 0.71 GB | 14.0 秒 |
| `2b`(既定) | 64.7 トークン毎秒 | 171.8 トークン毎秒 | 2.33 GB | 40.8 秒 |
| `8b` | 22.0 トークン毎秒 | 34.0 トークン毎秒 | 5.99 GB | 184.7 秒 |

- 生成の速度は、`npm run probe:speed` で、英語の段落 20 件を訳させたときの、全体の速度です。
- メモリの使用量は、llama-server が記録するメモリの内訳(モデル、文脈、計算用の領域の合計)です。モデルのファイルの分を含みます。`npm run model` が表示するコマンドに `-lv 4` を足して起動すると、記録に出ます。
- 論文 1 本の翻訳時間は、arXiv 1706.03762(104 段落)で、「この PDF を翻訳する」を押してから訳し終えるまでの時間です。レイアウト検出は、済ませた状態で測りました。
- 3 つとも、失敗した段落と、数式の目印がそろわず原文のまま残った段落は、0 件でした。`0.8b` では、1 段落が、文ごとの訳し直しになりました。
- 数式の目印が訳文に残る割合(`npm run probe:placeholders`、60 文)は、3 つとも 100% でした。
- 用語集の指定どおりになった件数(`npm run probe:glossary`、40 件)は、`0.8b` が 34 件、`2b` が 36 件、`8b` が 35 件でした。
- 訳文の良し悪しは、比べていません。arXiv 1706.03762 の 104 段落のうち、`2b` と一字一句同じ訳文だったのは、`0.8b` で 20 段落、`8b` で 25 段落でした。
- `31b` は、測っていません。ファイルの大きさ(19.53 GB)が、このパソコンで llama.cpp が GPU に使えると報告するメモリ(19.07 GB)を超えます。

既定は、`2b` のままにしています。
`8b` は、`2b` に比べて、評価値が 0.0038 高い一方で、論文 1 本の翻訳に 4.5 倍の時間がかかり、メモリを 2.6 倍使います。
`0.8b` は、`2b` の 3 分の 1 ほどの時間で訳し終えますが、評価値が 0.0230 低くなります。
評価値の差は、最も小さい `0.8b` と最も大きい `31b` の間で 0.0405 です。

`npm run model` は、llama-server に、モデルの名前(別名)を付けて起動します。
名前は、`plamo-3-translate-2b-Q4_K_M` のように、モデルの大きさと量子化の種類を含みます。
Web アプリは、訳文を、この名前ごとに分けて保存します。
`8b` に替えて起動した場合は、名前が `plamo-3-translate-8b-Q4_K_M` になり、`2b` で保存した訳文は使われません。
`2b` に戻すと、`2b` で保存した訳文が、また使われます。

そのほかの指定は次のとおりです。

| 指定 | 既定値 | 内容 |
| --- | --- | --- |
| `--port <番号>` | `8080` | llama-server が待ち受けるポート番号 |
| `--parallel <数>` | `4` | 同時に処理する依頼の数 |
| `--quant <種類>` | `Q4_K_M` | 量子化の種類。2026 年 11 月 14 日の時点で、`Q4_K_M`、`Q3_K_M`、`Q2_K` がすべての大きさにあり、`Q4_0` が `0.8b` と `2b` にあります[PFN 配布ページ (2026/11), 各 GGUF リポジトリのファイルの一覧] |
| `--dry-run` | なし | 起動せずに、実行されるコマンドだけを表示します。llama.cpp が無くても使えます。モデルの情報を読むので、インターネット接続は必要です |

`llama-server` の実行ファイルが PATH(コマンドを探す場所)に無い場合は、環境変数 `LLAMA_SERVER` にそのパスを指定します。
次の例の `/path/to/llama-server` を、実際のパスに置き換えます。

```bash
LLAMA_SERVER=/path/to/llama-server npm run model
```

## うまく動かないとき

| 表示 | 対処 |
| --- | --- |
| `llama-server が見つかりません。` | llama.cpp を導入します(手順 3)。導入してあるのに表示される場合は、環境変数 `LLAMA_SERVER` に実行ファイルのパスを指定します。`LLAMA_SERVER` を指定している場合は、表示の先頭がその値になります |
| `モデルの大きさは 0.8b、2b、8b、31b のいずれかで指定してください` | `npm run model` の 1 つ目の引数を、4 種類のどれかにします |
| `モデルの情報を読めませんでした。` | インターネット接続を確かめます。`--quant` を指定した場合は、その値も確かめます |
| `llama-server(http://127.0.0.1:8080)に接続できません。` | llama-server が起動しているかを確かめます |
| `… から、8 秒待っても応答がありません。` | 別のソフトが、その URL で待ち受けている可能性があります。接続は受け付けるものの、応答を返さないソフトがある場合の表示です |
| `llama-server が HTTP 404 を返しました` や `SyntaxError: ... is not valid JSON` | llama-server ではない別のソフトが、その URL で応答している可能性があります |
| 「翻訳サーバー」の画面の `モデルの別名(plamo-3-translate)に、モデルの大きさが入っていません。` | 2026 年 11 月 17 日より前の版の `npm run model` で起動した llama-server です。llama-server を Ctrl+C で止めて、`npm run model` で起動し直します。起動し直すと名前が変わるため、それまでに保存した訳文は使われず、開いた PDF は訳し直しになります |

「接続できません」「応答がありません」「HTTP 404」の 3 行に当てはまり、llama-server を起動しているはずの場合は、次の「ポート番号を変える方法」に進みます。
Web アプリでは、同じ内容が、「翻訳サーバー」の画面の「確かめる点」にも表示されます。

### ポート番号を変える方法

llama-server は、既定では 8080 番のポートを使います。
ポートは、1 台のパソコンの中で、通信の相手のソフトを区別するための番号です。
8080 番を別のソフトが使っている場合は、別の番号を指定します。

8080 番を使っているソフトは、macOS では次のコマンドで調べられます。
何も表示されなければ、8080 番は空いています。

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

たとえば 8081 番を使う場合は、起動するときと依頼するときの両方で指定します。

```bash
npm run model -- --port 8081
npm run probe:speed -- --base-url http://127.0.0.1:8081
```

Web アプリでは、「翻訳サーバー」の画面の「llama-server の URL」の欄を `http://127.0.0.1:8081` に書き換え、「接続を確かめる」を押します。

8080 番を別のソフトが使っている状態で `npm run model` を実行したときの表示は、まだ確かめていません。
