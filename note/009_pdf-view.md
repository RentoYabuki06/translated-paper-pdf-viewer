# 009 PDF の表示と、解析結果の確認用の表示

## 1. 目的

PDF を開いてページを表示し、PDF から読み取った行、段落、数式の文字の範囲を、ページの上に重ねて目で確かめられるようにします。
段落の検出と数式の検出は、あとで作る翻訳と訳文の重ね表示の土台になります。
外れ方を先に見ておくために、訳文の表示より前に、確認用の表示を作ります。
計画のマイルストーン M2 に当たります。

## 3. 設計判断

### 描画

- 各ページは、通常の描画と、文字を描かない描画の 2 枚の canvas に描きます。文字を描かない描画は、PDF.js の描画時の指定 `operationsFilter` で、文字を描く 4 つの命令(`showText`、`showSpacedText`、`nextLineShowText`、`nextLineSetSpacingShowText`)を飛ばして作ります。いまは切り替えて見るだけで、訳文を重ねるときに使います。
- 描画と解析は、表示範囲の上下 1 画面分まで近づいたページだけで行います。一度描画したページは、表示範囲から離れても破棄しません。長い PDF でのメモリの使用量は確かめていません。
- 倍率を変えると、描画済みのページをすべて描き直します。計画では「配置は 1 回だけ計算し、表示は CSS の拡大縮小で行う」としていますが、これは訳文の配置についての方針で、訳文を作るときに扱います。

### 文字の読み取り

- 文字の位置は、PDF.js の `getTextContent` が返す「文字のまとまり」の単位で扱います。1 文字ずつの位置は取得していません。LaTeX で作った PDF は、数式でフォントが変わるたびにまとまりが分かれるため、文中の数式はこの単位で区別できました。
- フォントの名前(`CMMI10` など)を得るために、PDF を読み込むときに `fontExtraProperties: true` を指定しました。この指定が無いと、PDF.js はフォントの名前を画面側に渡しません。この指定をすると、PDF.js はフォントのデータを破棄せずに持ち続けます。メモリへの影響は測っていません。
- まとまりの縦の範囲は、フォントが持つ高さの情報(ascent と descent)から決めます。値が範囲の外にあるフォント(大きな括弧用のフォントなど)は、既定の値(0.8 と −0.2)で代えます。そのため、大きな括弧や総和の記号の枠は、実際の字形より小さくなります。

### 行

- 2 つのまとまりは、縦の範囲が半分以上重なり、横のすき間が文字の大きさの 1.5 倍以下のときに、同じ行にします。最初は 1.0 倍にしましたが、両端ぞろえの行で文と文の間が 10.0 ポイント(文字の大きさ 10 ポイント)空いている箇所があり、行が 2 つに割れたため、1.5 倍に上げました。見本の 2 段組の論文の段の間隔は 22.5 ポイントで、1.5 倍(15 ポイント)より広いため、左右の段はつながりません。
- 行の縦の範囲は、添字より大きい文字だけで決めます。添字で範囲が上下に広がり、隣の行とつながるのを防ぐためです。

### 段落

- 行は、真上にある段落の最後の行と、文字の大きさ(差が 8% 以内)、行送り、横の重なりが合うときに、その段落へ足します。
- 段落の切れ目は、3 つの規則で判定します: 行送りが広がった(それまでの 1.25 倍を超える)、文字の大きさが変わった、行が字下げされている(左端が文字の大きさの 0.7 倍を超えて右にある)。
- 中央ぞろえの行(左端は違うが、中心が合っている)は、字下げとみなしません。複数行の題名を 1 つの段落にするためです。
- 段組は、特別に扱っていません。左右の段の行は横に重ならないため、別の段落になります。
- 行末のハイフンで分かれた語は、次の行が小文字で始まる場合に、ハイフンを除いてつなぎます。もともとハイフンを含む語(`self-attention` が行末で分かれた場合など)も、ハイフンが除かれます。
- レイアウト検出モデルが返す矩形は使っていません。計画のとおり、段落の矩形は文字の位置から作り、モデルは領域の種類の判定だけに使う予定です(M3)。

### 数式の文字

- 主に、フォントの名前で検出します。数式用のフォント(`CMMI`、`CMSY`、`CMEX`、`MSBM`、名前に `Math` を含むものなど)の文字を、数式の文字とします。
- 本文のフォントが Computer Modern でないページでは、`CMR` と `CMBX` の文字も数式とします。本文が Times 系の論文では、数式の中の数字、演算子、関数名(`softmax` など)、太字の変数が、これらのフォントで書かれるためです。等幅の `CMTT` は、URL やメールアドレスに使われるため含めません。
- 本文のフォントは、ページごとに、文字数が最も多いフォントとして決めます。数式ばかりのページでは、誤る可能性があります。文書全体で決める方法には、まだしていません。
- 補助として、数学記号とギリシャ文字だけでできたまとまりも、数式とします。
- 文字の大きさと上下のずれ(添字)による検出は、行っていません。数式の扱い(計画の M5)で足します。

### 画面

- 「PDF を開く」と「文章を貼り付けて訳す」は、両方を描画したまま、表示だけを切り替えます。切り替えても、開いた PDF や入力が消えないようにするためです。
- 文書の識別子(ファイルの内容のハッシュ値)は、まだ計算していません。訳文の保存を作るときに足します。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Node.js 26.13.1、Chrome です。
見本の PDF は、arXiv の 1512.03385(2 段組、12 ページ)と 1706.03762(1 段組、15 ページ)です。
どちらも、本文のフォントは Times 系(`NimbusRomNo9L-Regu`)でした。

- `npm test`: 135 件すべて成功。
- `npm run build`: 成功。`dist/pdfjs/` に 4 つのディレクトリが複製されました。まとめたファイルが 500 kB を超えるという警告が出ます。
- `npm run dev` で起動し、Chrome で `?arxiv=1512.03385` と `?arxiv=1706.03762` を開きました。どちらも arXiv から取得でき、ページが表示され、コンソールにエラーはありませんでした。
- 段落の枠: 1512.03385 の 1 ページ目と 3 ページ目、1706.03762 の 4 ページ目と 5 ページ目を目で見ました。本文の段落、節の見出し、図の説明文、脚注は、それぞれ 1 つの枠になっていました。左右の段はつながっていませんでした。
- 数式の文字: 上の 4 ページで、文中の数式(`F(x)`、`W_s`、`d_k` など)と、独立した数式が、橙色で塗られていました。本文の語が塗られている箇所は、見た範囲ではありませんでした。
- 文字を描かない描画: 1512.03385 の 3 ページ目では、本文の文字がすべて消え、脚注の上の罫線が残りました。4 ページ目の図は、枠と矢印が残り、中の文字は消えました。

### 見つかった誤り

- 1706.03762 の 4 ページ目の図(Figure 2)は、文字を描かない描画でも、図の中の文字(`MatMul`、`SoftMax` など)が残りました。図の上の題(`Scaled Dot-Product Attention`)は消えています。原因は調べていません。図の中の文字が、文字としてではなく図形として PDF に書かれていると推測します。図の中は訳さないため、このままでも支障はありません。
- 分数や根号の下にある小さい文字(1706.03762 の 4 ページ目の `√d_k` の `d_k`)が、行から外れて、1 行だけの別の段落になりました。
- 著者の欄(1706.03762 の 1 ページ目)は、横に並んだ著者のメールアドレスが 1 行につながり、段落が正しく分かれませんでした。著者の欄は訳さない予定です。
- 図の中の目盛りの数字や凡例(1512.03385 の 1 ページ目)は、1 つずつ別の段落になりました。本文との区別は、レイアウト検出(M3)で行います。
- 脚注の 1 行目にある URL の並びの末尾の語(`and`)が、別の段落になりました(1512.03385 の 1 ページ目)。

### 未確認

- 出版社版の PDF。見本を用意していません。
- ファイルの選択と、ドラッグ&ドロップで開く操作。ブラウザの自動操作では試せなかったため、arXiv の ID を指定する開き方だけを確かめました。
- 本文のフォントが Computer Modern の PDF での、数式の検出。
- 倍率の切り替えと、「行」「文字のまとまり」の枠の表示は、目で確かめていません。
- 見本の PDF の、上に挙げた以外のページ。
- 暗号化された PDF、壊れた PDF、ページ数の多い PDF。

## 5. 注意点・残課題

- 見本の PDF は、リポジトリに含めていません。
- arXiv の ID を指定して開くと、ブラウザが `https://arxiv.org/pdf/<ID>` から PDF を取得します。
- 計画の M2 の確認項目のうち、「見本の PDF 3 本」は 2 本(arXiv の 2 段組と 1 段組)で確かめました。出版社版が残っています。
- 「見つかった誤り」に挙げたものは、直していません。数式の断片は数式の扱い(M5)で、図の中の文字と著者の欄は、レイアウト検出(M3)と翻訳単位の組み立て(M4)で扱います。
