# 034 README にアーキテクチャ図を載せる

## 1. 目的

利用者から、別のアプリの図を参考にして、このアプリのアーキテクチャ図を作ってほしい、という依頼がありました。
参考の図は、部品をカードで、やりとりを矢印で表し、必須の構成を実線、任意の機能を破線で描き分けたものです。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `docs/architecture.svg` | 新規。アーキテクチャ図 |
| `README.md` | 「仕組み」の節の先頭に図を載せた。「ディレクトリの構成」に `docs/` を足した |

## 3. 設計判断

- 図は、SVG のファイルを手で書きました。GitHub の README にそのまま表示でき、文字を直すときに、図を作るソフトが要らないためです。
- 部品を、「インターネット」と「自分のパソコン」の 2 つの枠に分けました。このアプリの特徴は、PDF の解釈、レイアウト検出、翻訳を、パソコンの中で行うことなので、それが図から読み取れるようにしました。
- 線は 3 種類です。実線は必ず使う構成(Web アプリと llama-server)、破線は使わなくてもよい機能(arXiv からの取得、Ollama)、点線は初回だけ行うモデルのファイルの取得(Hugging Face から、検出モデルと翻訳モデル)です。参考の図は 2 種類でしたが、モデルの取得は「必須だが初回だけ」で、どちらにも当てはまらないため、3 種類にしました。
- アイコンは、単純な図形を自分で描きました。参考の図は、各サービスのロゴを使っていましたが、ロゴは使っていません。
- 文字は、利用者のパソコンにあるフォントで表示されます。フォントを埋め込んでいないので、環境によって、字の形と幅が少し変わります。

## 4. 動作確認

- `xmllint --noout docs/architecture.svg`: エラーなし。
- Chrome(画面を出さない実行)で SVG を 1280 × 680 の画像にして、目で確かめました。文字がカードからはみ出していないこと、矢印が部品に重なっていないことを確かめました。

## 5. 注意点・残課題

- 図の地の色は、明るい色に固定です。GitHub を暗い配色で見ても、図は明るいままです。
- 構成が変わったときは、SVG のファイルを直します。
