# 019 翻訳サーバーの設定と、接続の状態を確かめる画面

## 1. 目的

翻訳を依頼するソフトとその URL を、1 か所で設定し、接続できているかを確かめられるようにします。
これまでは、「PDF を開く」と「文章を貼り付けて訳す」の画面が、それぞれ llama-server の URL の欄を持っていました。
接続できないときに分かるのは、エラーの 1 行だけでした。
計画のマイルストーン M7 のうち、「接続状態の確認画面」に当たります。
あわせて、`note/018_ollama-backend.md` で足した Ollama への依頼を、画面から選べるようにします。

## 3. 設計判断

### 設定の持ち方

- 設定は、依頼するソフト(llama-server か Ollama)、それぞれの URL、Ollama のモデルの名前、Ollama に同時に依頼する数の 5 項目です。ブラウザの localStorage に、1 つの JSON として保存します。
- 以前の版は、llama-server の URL だけを、別の名前で保存していました。新しい設定が保存されていない場合は、その URL を引き継ぎます。開発に使っているブラウザで、8081 番の URL が引き継がれることを確かめました。
- 設定と接続の状態は、React の Context で、3 つの画面(PDF、貼り付け、翻訳サーバー)に渡します。どの画面も、同じ設定で依頼します。

### 接続の確認

- 確認は、3 つのときに行います: ページを開いたとき、「接続を確かめる」を押したとき、翻訳を始めるとき。翻訳を始めるときの確認で接続できなければ、翻訳を始めずに、「翻訳サーバー」の画面で設定を確かめるよう案内します。
- 設定を変えると、接続の状態は「まだ確かめていない」に戻ります。入力のたびに自動で確かめ直すことはしていません。URL を入力している途中の、未完成の URL に依頼を送らないためです。
- 接続の状態は、ページの右上に、依頼先と一緒にいつも表示します。押すと、「翻訳サーバー」の画面に切り替わります。

### 応答を待つ時間の上限

- 接続の確認には、応答を待つ時間の上限(8 秒)を設けました。
- 開発に使っているパソコンでは、8080 番のポートを別のソフト(OrbStack)が使っています。このソフトは、接続は受け付けますが、応答を返しません。上限が無いと、確認が「確かめています…」のまま終わりませんでした(「見つかった誤りと対処」)。
- 上限に達した場合は、「8 秒待っても応答がありません。別のソフトが、その URL で待ち受けている可能性があります」と表示します。

### 注意と案内

- 接続できた場合でも、次のときは注意を表示します。
  - モデルの名前に「plamo」が含まれない。PLaMo 3 Translate 以外のモデルでは、依頼の書式が合いません。
  - llama-server のモデルの別名が、`npm run model` が付けるもの(`plamo-3-translate`)と違う。別の方法で起動した llama-server では、起動時の指定が付いていない可能性があります。
  - 1 件の依頼で使える長さが、2,048 トークンより短い。
- 接続できなかった場合は、エラーの内容に続けて、確かめる点を表示します。内容は、README の「うまく動かないとき」と同じです。
- 注意は、名前と数値から機械的に出しています。llama-server が実際にどの指定で起動されたかは、応答からは分からないため、確かめていません。

### Ollama の項目

- Ollama を選ぶと、URL、モデルの名前、同時に依頼する数の欄が出ます。
- モデルの名前の欄には、Ollama に入っているモデルの名前を、入力の候補として出します。一覧は、接続を確かめるときに取り直します。
- 同時に依頼する数を利用者が指定する理由は、`note/018_ollama-backend.md` に書いたとおりです。
- 画面には、Ollama では llama-server の起動時の指定を渡せないことを、常に表示しています。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Node.js 26.13.1、Chrome、`npm run dev`、llama.cpp 1.0.0、Ollama 0.40.16 です。
llama-server は `npm run model -- --port 8081`(モデルは `2b`、Q4_K_M)で起動しています。

- `npm test`: 379 件すべて成功。
- `npm run build`: 成功。

### llama-server

- ページを開くと、右上に「llama-server(http://127.0.0.1:8081) — 接続済み: plamo-3-translate」と表示されました。以前の版が保存した URL が引き継がれています。
- 「翻訳サーバー」の画面で「接続を確かめる」を押すと、モデル `plamo-3-translate`、同時に処理できる依頼 4 件、1 件の依頼で使える長さ 2048 トークンと表示され、注意は出ませんでした。
- 使われていないポート(8999 番)を指定すると、「接続できません」と、確かめる点が表示されました。
- 応答を返さないポート(8080 番)を指定すると、8.0 秒後に「8 秒待っても応答がありません」と表示され、右上の表示が「接続できません」になりました。
- 設定を 8081 番に戻したあと、「文章を貼り付けて訳す」で 2 段落が訳され(1.2 秒)、「PDF を開く」で arXiv 1706.03762 の 104 段落が、保存した訳文で表示されました。

### Ollama

モデルは、手元の Ollama に入っていた `llama3.1:8b` を使いました。PLaMo 3 Translate ではないので、訳文としての意味はありません。通信と画面の確認です。

- Ollama を選んで「接続を確かめる」を押すと、モデルの名前が空の状態では「モデルの名前を指定してください」と表示され、入っているモデルの名前(2 つ)が候補に出ました。
- 存在しないモデルの名前では、「モデル「…」がありません」と表示されました。
- `llama3.1:8b` では、「接続できました」と、同時に処理できる依頼 1 件、1 件の依頼で使える長さ 2048 トークン、モデルの名前に「plamo」が含まれないという注意が表示されました。
- この設定のまま「文章を貼り付けて訳す」で 2 段落を依頼すると、どちらも「完了」になり、合計 173 トークンが 20.9 秒で返りました。時間には、モデルの読み込みを含みます。
- ページを読み込み直すと、Ollama の設定が残っていました。
- 確認のあと、設定を llama-server(8081 番)に戻し、Ollama のモデルの名前を空にしました。

### 見つかった誤りと対処

- 応答を返さないポートを指定すると、接続の確認が終わりませんでした。対処は「応答を待つ時間の上限」に書いたとおりです。

### 未確認

- PLaMo 3 Translate を Ollama で動かすこと(`note/018_ollama-backend.md` の未確認と同じです)。
- Ollama で、同時に依頼する数を 2 以上にした場合。
- 「PDF を開く」の画面から、Ollama に依頼すること。貼り付けの画面でだけ確かめました。
- 翻訳の途中で、設定を変えた場合の動作。翻訳の途中は、PDF の画面の「設定」のボタンを押せないようにしていますが、右上の表示からは「翻訳サーバー」の画面を開けます。
- localStorage が使えない場合(プライベートウィンドウなど)の動作。

## 5. 注意点・残課題

- 設定はブラウザごとです。別のブラウザや、別の URL で開いた Web アプリには、引き継がれません。
- 翻訳を始めるときに、毎回、接続を確かめます。応答を返さない依頼先を指定していると、翻訳が始まらないことが分かるまでに 8 秒かかります。
- 訳文の保存の鍵には、モデルの名前が入ります。llama-server と Ollama では、同じモデルでも名前が違うため、保存した訳文は共有されません。
