# 026 モデルの大きさごとに、保存した訳文を分ける

## 1. 目的

`npm run model` は、モデルの大きさ(`0.8b`、`2b`、`8b`、`31b`)と量子化の種類によらず、llama-server に同じ別名 `plamo-3-translate` を付けていました。
Web アプリは、訳文を、llama-server が知らせるモデルの名前(別名)ごとに分けて保存します(`note/011_pdf-translation.md`)。
そのため、`npm run model -- 8b` で起動し直しても、`2b` で保存した訳文が、`8b` の訳文として使われてしまいます。
`2b` 以外のモデルの速度を測る準備(README の「今後の予定」)で、メモリの測り方を調べているときに気づきました。
`8b` などは、まだ取得していないので、実際にこの取り違えが起きたことはありません。
モデルの大きさと量子化の種類が違えば、訳文が別々に保存されるようにします。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `scripts/lib/llamaArgs.ts` | 別名を、大きさと量子化の種類から作る(`modelAlias`)。例: `plamo-3-translate-2b-Q4_K_M` |
| `src/translate/settings.ts` | 接続したときの注意を、新しい別名の形に合わせる。以前の別名(`plamo-3-translate`)の llama-server には、起動し直すよう案内する |
| `tests/scripts/llamaArgs.test.ts`、`tests/translate/settings.test.ts` | テストを新しい別名に合わせ、3 件を追加 |
| `README.md` | 起動時の表示の例、接続の表示、保存した訳文の説明、「モデルの大きさと起動時の指定」、「うまく動かないとき」を更新 |

## 3. 設計判断

- 別名は、`plamo-3-translate-<大きさ>-<量子化の種類>` の形にしました。保存する訳文の鍵には、すでにモデルの名前が入っています。名前を変えるだけで、鍵の作り方を変えずに、訳文が分かれます。
- 既定のモデル(`2b`、Q4_K_M)でも、大きさと量子化の種類を付けます。選ばなかった方法は、既定のモデルだけ、これまでの別名 `plamo-3-translate` のままにする方法です。この方法では、これまでに保存した訳文をそのまま使えます。しかし、あとで既定のモデルを替えると、同じ別名が別のモデルを指すことになり、同じ取り違えが起きます。既定の大きさは、見直す予定です。
- 選ばなかった方法は、もう 1 つあります。llama-server が知らせるモデルのファイルの名前を、保存する訳文の鍵に足す方法です。別名を変えずに済みますが、鍵の作り方が、llama-server と Ollama で分かれます。
- これまでに保存した訳文を、新しい別名で使えるようにする処理は、入れていません。以前の別名の訳文が、どの大きさのモデルで作られたかを、アプリは知りません。開発に使っているパソコンでは `2b` だけですが、それを前提にした処理を残すことになります。
- 以前の別名で起動したままの llama-server には、「翻訳サーバー」の画面で、起動し直すよう案内します。これまでは、別名が違う場合に「`npm run model` 以外の方法で起動した可能性」と表示していました。以前の版で起動した llama-server に、この文を出すと、原因を取り違えます。
- アプリの側では、別名の形を、正規表現で確かめます。大きさの一覧(`0.8b` など)を、アプリの側には書いていません。起動用のコマンドの側だけを直せば、大きさを足せるようにするためです。
- `--alias` を付けずに起動した llama-server は、別名として、モデルの取得元の指定(`pfnet/plamo-3-translate-2b-GGUF:Q4_K_M`)を知らせます(llama.cpp 1.0.0 で確かめました)。新しい別名の形とは重なりません。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Node.js 26.13.1、Chrome 157、llama.cpp 1.0.0 です。

- `npm test`: 440 件すべて成功。
- `npm run build`: 成功。
- `npm run model -- --dry-run`: 表示されたコマンドに `--alias plamo-3-translate-2b-Q4_K_M` が入りました。
- `npm run model -- 8b --quant Q3_K_M --dry-run`: `--alias plamo-3-translate-8b-Q3_K_M` が入りました。
- `npm run model -- --port 8082` で、一時的に llama-server を起動しました(モデルは、取得済みの `2b`)。`/props` の `model_alias` は `plamo-3-translate-2b-Q4_K_M` でした。
- `llama-server -hf pfnet/plamo-3-translate-2b-GGUF:Q4_K_M` を、`--alias` を付けずに一時的に起動すると、`model_alias` は `pfnet/plamo-3-translate-2b-GGUF:Q4_K_M` でした。

以下は、`npm run dev` のページを Chrome で開いて確かめました。

- 以前の別名のままの llama-server(8081 番。この変更の前から起動していたもの)に接続すると、「翻訳サーバー」の画面に、「モデルの別名(plamo-3-translate)に、モデルの大きさが入っていません。…llama-server を起動し直してください。」と表示されました。接続と翻訳は、これまでどおりできました。
- URL を、一時的に起動した llama-server(8082 番)に書き換えて「接続を確かめる」を押すと、「接続できました。」と表示され、モデルは `plamo-3-translate-2b-Q4_K_M`、注意は表示されませんでした。ページの右上の表示は、`接続済み: plamo-3-translate-2b-Q4_K_M` になりました。
- arXiv 1706.03762 を、8081 番で翻訳したあと(依頼 0 件、再利用 104 件)、8082 番に切り替えて翻訳しました。依頼 104 件、再利用 0 件、失敗 0 件、原文のまま残った段落 0 件で、40.8 秒かかりました(レイアウト検出は済んだ状態。測定は 1 回)。別名が変わったので、保存してあった訳文は使われませんでした。
- 8082 番で得た 104 段落の訳文は、8081 番の訳文と、一字一句同じでした。モデルと起動時の指定は、別名のほかは同じです。
- 確認のあと、一時的に起動した llama-server は止め、ブラウザの設定は 8081 番に戻しました。

### 未確認

- `2b` 以外のモデルを実際に起動した場合。`8b` などは取得していないので、別名は、起動せずに表示したコマンド(`--dry-run`)で確かめただけです。
- 大きさの違うモデルで、訳文が実際に分かれて保存されること。上の確認は、同じ `2b` で別名だけを変えたものです。

## 5. 注意点・残課題

- この変更の前から起動している llama-server は、起動し直すまで、以前の別名のままです。起動し直すと、それまでに保存した訳文は使われなくなり、開いた PDF は訳し直しになります。
- 以前の別名で保存した訳文は、ブラウザに残ります。保存した訳文を消す操作は、まだありません。
- Ollama では、モデルの名前は、利用者が付けたものです。大きさの違うモデルに同じ名前を付けると、同じ取り違えが起きます。アプリは、これを防ぎません。
- `note/021_probe-backends.md` に書いた注意(位置符号化の補正を付けずに起動した llama-server に、同じ別名を付けて、ブラウザから依頼しない)は、そのまま当てはまります。別名は、起動時の指定の違いまでは表しません。
