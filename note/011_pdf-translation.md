# 011 PDF の翻訳と、訳文の重ね表示

## 1. 目的

開いた PDF の段落を訳し、訳文を元の段落の位置に重ねて表示します。
これで、論文を日本語で読むところまでがつながります。
訳文は保存し、同じ PDF を開き直したときに、翻訳をやり直さずに表示します。
計画のマイルストーン M4 に当たります。

## 3. 設計判断

### 状態の持ち方

- ページの解析とレイアウト検出を、ページの表示の部品(`PageView`)から、文書ごとの `DocumentSession` へ移しました。画面に出ていないページも、先に解析して翻訳を依頼できるようにするためです。
- レイアウト検出は、表示用の描画とは別に、検出用の大きさ(幅 800 画素)で描画した画像を入力にするように変えました。`note/010_layout-detection.md` では、表示の倍率のまま入力にしていました。表示の倍率で結果が変わらなくなり、表示していないページも検出できます。代わりに、検出するページは 2 回描画されます。
- 画面の部品は、React の `useSyncExternalStore` で、ページごとの状態を読みます。1 つの段落の訳文が届いたときに、そのページの部品だけが描き直されます。

### 翻訳単位

- 1 段落を、1 つの翻訳単位にします。段組やページをまたぐ段落の結合は、行っていません(計画の M6)。
- 訳すのは、レイアウト検出で訳す種類(`note/010_layout-detection.md`)になった段落です。そのうち、次の段落は訳しません。
  - 数式の文字が半分以上を占める段落
  - 2 文字以上続く英字を含まない段落
  - 題名(`doc_title`)と要旨(`abstract`)の領域の間にある段落。著者の名前と所属に当たります。節の見出しは除きません
- 文中の数式は、置き換えずに、PDF から読み取った文字のまま送ります(計画の M5 で扱います)。
- 文脈の欄(論文の題名、節の見出し、直前の段落)は、使っていません。計画では使う予定でしたが、文脈を入れたときの訳文への影響を確かめていないため、入れずに始めました。
- 原文の言語は `en`、訳先は `ja`、文体は `plain`(だ・である調)、訳文の長さの上限は 1,024 トークンに固定しています。上限を超える長い段落を、文単位に分ける処理はありません。

### 順番待ち

- 同時に依頼する数は、llama-server が報告する同時処理数に合わせます。
- 順番は、表示中のページ、その後ろのページ、表示中より前のページの順です。優先度は、依頼を始める時点で計算し直すため、途中でページを送ると、送った先のページが先に訳されます。
- 表示中のページは、画面の中央の高さにかかっているページとしています。
- 翻訳単位の組み立て(解析と検出)も、同じ順でページを進めます。組み立てと依頼は並行して進みます。

### 訳文の保存

- 保存先は IndexedDB です。鍵は、「モデルの名前、生成の設定の版、訳文の長さの上限、依頼の文字列全体」の SHA-256 です。
- 依頼の文字列そのものを鍵に含めるため、段落の検出の方法を変えて原文が変わると、その段落だけが訳し直されます。実際に、段落の判定を直したあとで開き直したとき、146 段落のうち 135 段落が再利用され、11 段落だけが依頼されました。
- 文書の識別子(ファイルの内容のハッシュ値)は、鍵に使っていません。同じ文の段落は、別の論文でも同じ訳文が使われます。
- 長さの上限に達して途中で切れた訳文と、失敗した依頼は、保存しません。
- レイアウト検出の結果は、保存していません。開き直すと、検出はやり直します。

### 重ね表示

- 層は、下から順に、通常の描画、文字を描かない描画、訳文、確認用の枠です。文字を描かない描画は、CSS の `clip-path` で、訳文を表示している段落の範囲だけを見せます。元の文字だけが消え、背景や罫線は残ります。
- 消す範囲は、段落の範囲を、左右に 1 ポイント、上下に 2 ポイント広げたものです。文字の上下のはみ出しを消すためです。
- 訳文の層の中の座標は、ページのポイントで書き、層全体を CSS の `transform: scale()` で倍率に合わせます。倍率を変えても、訳文を収める計算はやり直しません。
- 訳文を収める設定は、計画の順で探します: 元の文字の大きさと行送り、下の空きへ広げる、行送りを 1.2 倍に詰める、文字を 95% から 67% まで 7 段階で小さくする(6 ポイント未満にはしない)。どれでも収まらない場合は、末尾を隠して印を付けます。高さは、ブラウザに実際に組ませて測ります。
- 原文の範囲は、文字の上端から下端までで、行の上下の余白を含みません。同じ行数の訳文が「収まらない」と判定されないよう、範囲の高さに、文字の大きさの 0.35 倍を足して比べます。
- 下の空きは、真下にある最も近い段落か、図・表・独立した数式の領域の、3 ポイント手前までです。
- 1 行だけの段落(見出しなど)は、右の空きまで幅を広げます。題名は、元の範囲の中で中央にそろえます。
- 書体は、本文を明朝体、題名と見出しをゴシック体の太字にしました。原文の 1 行目が字下げされている段落は、訳文も 1 文字分字下げします。
- 訳文は、訳し終えてから表示します。生成の途中の訳文は表示しません。途中の訳文で収める計算を繰り返さないためです。

## 4. 動作確認

環境は、macOS 26.6(Apple M5、メモリ 24 GB)、Node.js 26.13.1、Chrome、`npm run dev`、llama.cpp 1.0.0 です。
llama-server は `npm run model -- --port 8081`(モデルは `2b`、Q4_K_M、同時処理数 4)、レイアウト検出は WebGPU です。

- `npm test`: 185 件すべて成功。
- `npm run build`: 成功。

### 翻訳

| 論文 | ページ数 | 翻訳単位 | 依頼 | 時間(秒) | 失敗 | 途中で切れた訳文 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| arXiv 1706.03762(1 段組) | 15 | 109 | 107 | 47 | 0 | 0 |
| arXiv 1512.03385(2 段組) | 12 | 146 | 計 157 | 測っていません | 0 | 0 |

- 時間は、「この PDF を翻訳する」を押してから、すべての翻訳単位を訳し終えるまでです。レイアウト検出の時間を含みます。測定は 1 回です。
- 1706.03762 の依頼が翻訳単位より 2 件少ないのは、保存してあった訳文が 2 件使われたためです。先に訳した 1512.03385 に、同じ文の段落がありました。
- 1512.03385 は、段落の判定を直す前に 137 単位を訳し、直したあとに開き直して 11 件を依頼しました。そのため、通しの時間は測れていません。直す前の回は、20 秒で 35 単位、約 65 秒で 128 単位まで進みました。
- 計画の確認項目「論文 1 本を日本語で読める」: 2 本とも、本文、要旨、題名、節の見出し、図表の説明文、脚注が日本語で表示されました。図、表、独立した数式、著者の欄、ページ番号は、原文のまま残りました。目で見たのは、1512.03385 の 1 ページ目と 3 ページ目、1706.03762 の 2 ページ目です。

### 訳文の保存

- 1512.03385 を開き直して「この PDF を翻訳する」を押すと、依頼は 0 件で、146 単位すべてに保存した訳文が使われました。表示までは 5.0 秒で、大半はレイアウト検出の時間です。
- 計画の確認項目「開き直すと依頼が 0 件で表示される」を満たしました。

### 訳文の収まり

すべてのページを表示させてから、訳文の箱が使った設定を数えました。

| 論文 | 元のまま | 下へ広げた | 行送りを詰めた | 文字を小さくした | 末尾を隠した |
| --- | ---: | ---: | ---: | ---: | ---: |
| arXiv 1512.03385 | 68 | 20 | 0 | 58 | 0 |
| arXiv 1706.03762 | 36 | 34 | 0 | 39 | 0 |

- 計画の確認項目「箱に収まらない段落が 5% 未満」: 末尾を隠した訳文は、2 本とも 0 件でした。
- 文字を小さくした訳文が 4 割ほどあります。どの程度小さくなったかの内訳は、数えていません。1512.03385 の 3 ページ目で見た範囲では、95%(10 ポイントが 9.5 ポイント)でした。
- 「行送りを詰めた」が 0 件なのは、原文の行送りがもともと文字の大きさの 1.2 倍ほどで、詰める余地が無いためです。

### 操作

- 訳文をクリックすると、その段落が原文の表示に戻り、訳文の箱が 1 つ減りました。
- 「訳文を表示」のチェックを外すと、訳文の箱が 0 個になりました。
- 表示中のページから先に訳されることは、1512.03385 で、ボタンを押した 20 秒後に 1 ページ目が訳文になっていることで確かめました。途中でページを送ったときに順番が変わることは、単体テストだけで確かめています。

### 見つかった誤りと対処

- 幅いっぱいの行の次に、字下げされた幅いっぱいの行が来ると、段落が分かれず、2 つか 3 つの段落が 1 つにつながっていました。つながった段落は、複数の検出領域にまたがるため種類が `unknown` になり、訳されませんでした(1512.03385 の 3 ページ目の右の段)。原因は、中央ぞろえの判定でした。字下げが 1 文字分のとき、行の中心は 0.5 文字分しかずれず、許容の 1.0 文字分に収まっていました。許容を 0.25 文字分に下げ、テストを足しました。直したあと、3 ページ目の段落は 22 個から 25 個になり、右の段もすべて訳されました。

### 直していない誤り

- 文中の数式は、上付きと下付きが失われた文字のまま、訳文に入ります(`ht−1`、`x1` など)。訳文の中での位置が、原文と変わっていることもあります。
- 段組やページをまたぐ段落は、途中で分かれたまま、別々に訳されます。文の途中から始まる段落の訳文は、不自然になります。
- 訳文が原文より短い段落は、下に空きができます。
- 分数や根号の下の小さい文字は、別の段落として検出されるため(`note/009_pdf-view.md`)、訳文を表示した段落の範囲に入っていると、元の文字ごと消えます。

### 未確認

- 「中止」のボタン、llama-server に接続できない場合の表示、依頼が失敗した段落の表示。
- 長さの上限(1,024 トークン)に達した訳文の表示。2 本では 0 件でした。
- 訳文の内容の正しさ。読んで不自然でないことを数段落で見ただけで、原文と突き合わせてはいません。
- 倍率を変えたときの訳文の表示。
- 翻訳の最中に別の PDF を開いた場合の動作。
- 出版社版の PDF。
- IndexedDB が使えない場合(プライベートウィンドウなど)の動作。

## 5. 注意点・残課題

- 翻訳には、llama-server の起動が必要です。開発に使っているパソコンでは、8081 番のポートで起動しています。
- 保存した訳文を消す操作がありません。消す場合は、ブラウザの設定で、このサイトのデータを削除します。
- 保存の鍵に文書の識別子を含めていないため、訳文は文書をまたいで共有されます。
- 文脈の欄を使っていません。訳語が段落によって変わる可能性があります。
- 一度描画したページと、その訳文の箱は、表示範囲から離れても破棄しません。ページ数の多い PDF でのメモリの使用量は確かめていません。
