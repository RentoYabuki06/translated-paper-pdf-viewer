# 008 貼り付けた英文を訳す画面と、実物の llama-server での確認

## 1. 目的

ブラウザから llama-server までを通して、翻訳を試せるようにします。
これまでの画面はアプリの名前と説明文だけで、翻訳の処理は実験用のコマンドからしか呼べませんでした。
あわせて、これまで確かめられていなかった実物の llama-server での動作を確かめ、結果を記録します。

## 3. 設計判断

- PDF の表示より先に、英文を貼り付ける最小の画面を作りました。通信の処理はすでにあり、小さな変更でブラウザから llama-server までがつながるためです。PDF の表示、段落の検出、訳文の重ね表示は、この画面とは別に作ります。
- llama-server の URL は、画面の欄で指定し、ブラウザの localStorage に覚えさせます。開発に使っているパソコンでは OrbStack が 8080 番のポートを使っており、既定の URL のままでは接続できないためです。環境変数で指定する方法は、変えるたびに開発用のサーバーを起動し直す必要があるので選びませんでした。
- 段落の区切りは空行にし、段落の中の改行は空白 1 つに置き換えます。PDF から写した文章は、行の折り返しの位置に改行が入っているためです。行末のハイフンで分かれた語(`trans-` と `lation`)は、つなぎ直していません。
- 同時に依頼する数は、llama-server が報告する同時処理数に合わせます。翻訳を始める前に毎回 `/props` を読み、接続できない場合は翻訳を始めずにエラーを表示します。
- 1 段落の依頼が失敗しても、ほかの段落の翻訳は続けます。`mapWithConcurrency` は 1 件の失敗で全体を失敗にするので、段落ごとの処理の中で失敗を受け止めています。
- `mapWithConcurrency` は、`scripts/lib/` から `src/lib/` へ移しました。Web アプリから `scripts/` の中のファイルを読み込む形を避けるためです。
- 訳文の文体は「だ・である調」(`form: 'plain'`)、1 段落の訳文の長さの上限は 1,024 トークンに固定しています。どちらも実験用のコマンドと同じ値です。
- 画面の下に「Built with PLaMo」と表示します。

## 4. 動作確認

環境は、macOS 26.6(Apple M5、メモリ 24 GB)、Node.js 26.13.0、Chrome、llama.cpp 1.0.0(build 12359、Homebrew で導入)です。
llama-server は `npm run model -- --port 8081` で起動しました(モデルは `2b`、Q4_K_M)。

### 実物の llama-server

- `npm run model -- --port 8081`: 初回のモデルの取得と読み込みが終わり、`curl http://127.0.0.1:8081/health` が `{"status":"ok"}` を返しました。
- `/props` の応答: 同時処理数 4、1 依頼あたりの文脈の長さ 2,048(`--ctx-size 8192` を 4 で割った値)。
- `http://localhost:5173` からの依頼に対して、`/props` と `/completion` の事前確認(OPTIONS)の両方が `Access-Control-Allow-Origin: http://localhost:5173` を返しました。ブラウザから直接依頼できます。

### `npm run probe:speed -- --base-url http://127.0.0.1:8081`

段落 20 件(原文は合計 1,391 語)。測定は 1 回です。

| 同時依頼数 | 生成トークン | 時間(秒) | 全体の速度(トークン毎秒) | 1 依頼の速度(トークン毎秒、中央値) | 上限で停止 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 2159 | 33.0 | 65.4 | 68.9 | 0 |
| 2 | 2159 | 24.6 | 87.6 | 54.2 | 0 |
| 4 | 2159 | 12.4 | 173.8 | 48.0 | 0 |

### `npm run probe:placeholders -- --base-url http://127.0.0.1:8081`

文 60 件(数式は合計 133 か所)。測定は 1 回です。

| 書式 | 文の数 | 厳密に合格 | 表記を直して合格 | 上限で停止 |
| --- | ---: | ---: | ---: | ---: |
| bare | 60 | 60(100.0%) | 60(100.0%) | 0 |
| paired | 60 | 60(100.0%) | 60(100.0%) | 0 |
| bare+pin | 60 | 60(100.0%) | 60(100.0%) | 0 |
| paired+pin | 60 | 59(98.3%) | 59(98.3%) | 0 |

`paired+pin` の不合格 1 件は、閉じタグ `</m2>` が訳文から抜けたものです。

```text
原文: Then the iterates satisfy <m1>f(xk) − f(x⋆) ≤ L∥x0 − x⋆∥2/(2k)</m1> for all <m2>k ≥ 1</m2>.
訳文: すると、反復値はすべての <m2>k ≥ 1 に対して <m1>f(xk) − f(x⋆) ≤ L∥x0 − x⋆∥2/(2k)</m1> を満たす。
```

### 画面

- `npm test`: 85 件すべて成功。
- `npm run build`: 成功。
- `npm run dev` で起動し、Chrome で `http://localhost:5173/` を開いて、URL の欄を `http://127.0.0.1:8081` にした状態で「翻訳する」を押しました。接続の表示は「モデル: plamo-3-translate、同時処理数: 4、文脈の長さ: 2048」になり、見本の 2 段落の訳文が原文の右に表示されました(0.9 秒、73 トークン)。ブラウザのコンソールにエラーはありませんでした。

### 未確認

- 「中止」のボタン、接続できない場合のエラーの表示、1 段落が失敗した場合の表示、上限に達した場合の表示は、ブラウザで操作して確かめていません。
- 長い文章(数十段落)を貼り付けた場合の動作。
- 8080 番のポートでの llama-server の起動。
- `2b`・Q4_K_M 以外のモデル。

## 5. 注意点・残課題

- 訳文は保存されません。ページを読み込み直すと消えます。
- 1 依頼あたりの文脈の長さは 2,048 トークンです。原文と訳文の合計がこれを超える長い段落は、llama-server がエラーを返すか、訳文が途中で切れます。段落を自動で分ける処理はありません。
- 行末のハイフンで分かれた語は、つなぎ直しません。
- 数式を目印に置き換える処理は、この画面では使っていません。
- 8080 番のポートを OrbStack などが使っている場合は、`npm run model -- --port 8081` で起動し、画面の URL の欄も書き換える必要があります。
