# 021 依頼先どうしの訳文を比べる実験

## 1. 目的

`note/018_ollama-backend.md` で、翻訳の依頼先に Ollama を足しました。
Ollama には、llama-server の起動時に渡している位置符号化の補正(`note/004_llama-launcher.md`)を渡す手段が、見つかっていません。
補正が無いと訳文がどう変わるのかは、分かっていませんでした。
これを調べるために、同じ依頼を複数の依頼先に送り、訳文が一字一句同じかどうかを比べる実験を、1 コマンドで行えるようにします。
Ollama や llama.cpp の版が上がったときに、同じ比較をやり直す用途も想定しています。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `scripts/probe-backends.ts` | 新規。実験の本体。長さの違う入力を、依頼先ごとに訳させ、訳文を比べる |
| `scripts/lib/compare.ts` | 新規。2 つの訳文が最初に違う位置を求める処理と、その前後を切り出す処理 |
| `scripts/lib/cli.ts` | Ollama に起因する失敗も、短い案内だけを表示するようにした |
| `tests/scripts/compare.test.ts` | 新規。上の `compare.ts` のテスト 7 件 |
| `package.json` | コマンド `probe:backends` を追加 |
| `README.md` | コマンドの一覧と、模擬サーバーでの実行の例に、このコマンドを足した |

コマンドの指定は次のとおりです。

| 指定 | 内容 |
| --- | --- |
| `--llama <URL>` | 比べる llama-server の URL。複数回、指定できる |
| `--ollama-model <名前>` | 比べる Ollama のモデルの名前。指定すると、Ollama が依頼先に加わる |
| `--ollama-url <URL>` | Ollama の URL。既定は `http://127.0.0.1:11434` |
| `--sentences <数の並び>` | 入力の文の数。カンマで区切って指定する。既定は `5,10,20,30` |

依頼先は、合わせて 2 つ以上 8 つ以下で指定します。

## 3. 設計判断

- **訳文を、一字一句比べます。** アプリの生成の設定は、最も確率の高いトークンを選び続けるものです。同じ計算をしている依頼先は、同じ入力に同じ訳文を返します。訳文が 1 文字でも違えば、依頼先の間で、計算のどこかが違っています。訳文の良し悪しは、この実験では判断しません。
- **アプリと同じ依頼の処理を使います。** `src/translate/` の `LlamaServerBackend` と `OllamaBackend` を、そのまま呼びます。アプリが送る依頼と、同じ項目の依頼で比べるためです。
- **入力の長さを変えます。** 位置符号化の補正が無い場合の誤差は、入力が長いほど大きくなると説明されています(`scripts/lib/yarn.ts` の冒頭)。短い入力だけでは、違いが出ない可能性があります。入力は、実験用の文(`scripts/data/mathSentences.ts`)を前から順につないだ段落で、文の数で長さを変えます。
- **依頼は、1 件ずつ送ります。** 同時に送ると、同じパソコンの上で計算の資源を取り合い、時間を比べられません。
- **最初に、短い依頼を 1 件ずつ送ります。** Ollama は、使われていないモデルをメモリから降ろします(Ollama の説明書の FAQ によると、既定では 5 分後)。最初の依頼にモデルの読み込みの時間が入ると、時間を比べられないためです。
- **違いがあっても、終了コードは 0 にします。** 実験の結果を表示するコマンドであり、合否を判定するものではないためです。
- 違いが見つかった場合は、最初に違う位置と、その前後の訳文を表示します。入力は自作の文なので、訳文をそのまま表示しています。

## 4. 動作確認

環境は、macOS 26.6(Apple M5、メモリ 24 GB)、Node.js 26.13.1、llama.cpp 1.0.0、Ollama 0.40.16 です。

- `npm test`: 386 件すべて成功(このうち、足したテストは 7 件)。
- `npm run build`: 成功。
- 模擬サーバー(`npm run mock`)の URL を 2 回指定して実行し、表と「訳文は同じ」が表示されることを確かめました。
- 次の場合に、短い案内が表示され、終了コードが 1 になることを確かめました: 依頼先の指定が 1 つ以下、文の数の指定が整数でない、Ollama に無いモデルの名前、起動していない llama-server の URL。

### 実験の結果

次の 3 つを比べました。
モデルのファイルは、3 つとも同じ(`2b`、Q4_K_M)です。

| 依頼先 | 内容 |
| --- | --- |
| A | `npm run model -- --port 8081` で起動した llama-server。位置符号化の補正あり(同時処理数 4、文脈の長さ 8,192) |
| B | A と同じ指定から、補正の 2 つ(`--yarn-beta-fast`、`--yarn-beta-slow`)だけを外して起動した llama-server。この実験のために一時的に起動し、終わったあとで止めた |
| C | Ollama。モデルは、llama-server が取得したファイルを、`ollama create` で取り込んだもの |

実行したコマンドは、次のとおりです。

```bash
npm run probe:backends -- --llama http://127.0.0.1:8081 --llama http://127.0.0.1:8082 --ollama-model plamo-3-translate-2b
```

| 入力 | 入力トークン | A と B | A と C | B と C |
| --- | ---: | --- | --- | --- |
| 5 文 | 96 | 同じ | 同じ | 同じ |
| 10 文 | 176 | 同じ | 同じ | 同じ |
| 20 文 | 358 | 違う(465 文字目から) | 違う(465 文字目から) | 同じ |
| 30 文 | 557 | 違う(464 文字目から) | 違う(464 文字目から) | 同じ |

- **Ollama(C)の訳文は、4 通りの入力すべてで、補正なしの llama-server(B)と一字一句同じでした。**
- 補正ありの llama-server(A)だけが、20 文と 30 文の入力で、違う訳文を返しました。
- 違いは、20 文と 30 文のどちらも、同じ文から始まりました。違いが始まる箇所の訳文は、補正あり(A)が「L-平滑」、補正なし(B と C)が「L-smooth」でした(原文は "L-smooth")。
- 入力のトークン数は、3 つの依頼先で同じでした。出力のトークン数は、30 文の入力で、A が 641、B と C が 642 でした。ほかの入力では、3 つとも同じでした。
- 1 件ずつ送ったときの速度は、3 つとも 61 から 67 トークン毎秒で、差はありませんでした。

このコマンドを作る前に、補正なしの llama-server を、同時処理数 1・文脈の長さ 2,048(Ollama への依頼と同じ長さ)でも起動して、同じ 4 通りの入力を訳させました。
その訳文も、4 通りすべてで、B と C の訳文と同じでした。

### 分かったこと

- Ollama と `npm run model` の llama-server の訳文の違いは、位置符号化の補正の有無で説明できます。Ollama 0.40.16 は、確かめた入力では、補正を付けない llama.cpp 1.0.0 と同じ訳文を返します。
- 補正の有無で訳文が変わったのは、確かめた 4 通りのうち、長いほうの 2 通りです。5 文と 10 文の入力では、変わりませんでした。
- どちらの訳文が良いかは、この実験では判断していません。補正は、PFN の公式の道具(plamo-translate-cli)が llama-server に渡しているものです(`scripts/lib/yarn.ts` の冒頭)。

### 未確認

- `2b`・Q4_K_M 以外のモデルでの比較。
- 文脈や数式の目印を付けた依頼での比較。このコマンドの入力は、数式を文字のまま埋め込んだ段落だけです。
- 違いが出はじめる入力の長さ。10 文(176 トークン)と 20 文(358 トークン)の間は、調べていません。

## 5. 注意点・残課題

- 補正なしの llama-server を起動するコマンドは、用意していません。この実験では、`npm run model` が実行する llama-server のコマンドから、`--yarn-beta-fast` と `--yarn-beta-slow` とその値を除き、ポート番号を 8082 に変え、モデルの指定を取得済みのファイル(`-m <ファイルの場所>`)に変えて、手で実行しました。
- 補正なしの llama-server に、アプリ(ブラウザ)から依頼しないでください。モデルの別名が同じなので、保存した訳文の鍵が、補正ありの場合と同じになります。補正なしの訳文が保存されると、あとで補正ありの llama-server を使ったときにも、その訳文が使われます。この実験では、Node.js のコマンドからだけ依頼しました。
- 速度の列は、依頼を送ってから訳文を受け取り終えるまでの時間で、出力のトークン数を割った値です。サーバーが報告する生成の速度とは、少し違います。
