# 031 PDF の画面の操作の帯を、少ない項目にまとめる

## 1. 目的

利用者から、PDF の画面がごちゃごちゃしているので、シンプルにしたい、という依頼がありました。
具体的には、次の 2 点です。

- ファイルの名前、解析結果の表示、レイアウト検出の 3 行は不要なので、消す。
- arXiv から開く欄は残すが、「PDF のファイルを選ぶ」の横に並べて、場所を取らないようにする。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `src/viewer/PdfViewer.tsx` | 開く操作を 1 行にまとめた。操作の帯を、翻訳のボタン、訳文の表示、原文を左に並べる、倍率、用語集、訳文の比較、PDF への保存の 1 行にした。解析結果の表示とレイアウト検出の操作は、URL に `?debug` を付けたときだけ出す。進み具合の表示を短くした |
| `src/App.tsx` | `PdfViewer` に渡していた、翻訳サーバーの設定を開く処理を外した |
| `src/index.css` | 開く操作の行と、帯の右寄せ、状態の行の見た目 |
| `README.md` | 「PDF を開く」の節を、新しい画面に合わせた |

## 3. 設計判断

- 解析結果の表示(段落、行、文字のまとまり、文中の数式、検出した領域、文字を描かない描画)と、レイアウト検出の操作(実行の方法、有効と無効)は、コードから消さず、URL に `?debug` を付けたときだけ出すようにしました。検出の誤りを調べるときと、WebGPU が使えない環境で WebAssembly を選ぶときに、要るためです。
- ふだんの画面では、確認用の枠を、初めから表示しません。以前は、段落と文中の数式の枠が、初めから表示されていました。切り替えるチェックボックスが無くなるので、表示したままにはできません。
- 倍率は、依頼の 3 行の中にありましたが、残しました。原文を左に並べる表示では、画面の幅に合わせて倍率を下げる必要があるためです。帯の 1 行目に移しました。
- 帯にあった「翻訳: (依頼先)」の表示と「設定」のボタンは、消しました。同じ内容が、画面の右上の接続の表示にあり、押すと設定の画面が開きます。
- 進み具合は、「翻訳が終わりました: 104 / 104 段落」のように、段落の数だけにしました。失敗と、原文のままの段落は、1 件以上あるときだけ足します。以前の内訳(依頼の件数、再利用の件数など)は、表示にマウスを重ねると出ます。
- レイアウト検出のモデルの取得の進み具合と、失敗の知らせは、`?debug` が無くても、帯の下に出します。初回は 130.5 MB の取得があり、何も出ないと、止まって見えるためです。
- ドラッグ&ドロップの案内は、PDF を開く前だけ表示します。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Chrome 157 です。`npm run dev` のページで確かめました。

- `npm test`: 467 件すべて成功。
- `npm run build`: 成功。
- arXiv 1706.03762 を開くと、開く操作が 1 行、帯が 1 行で表示されました。確認用の枠は、表示されませんでした(枠の数 0)。
- 「この PDF を翻訳する」を押すと、保存してある訳文で翻訳が終わり、帯の下に「翻訳が終わりました: 104 / 104 段落」と表示されました。表示の `title` に、以前の内訳が入っていました。

- URL に `?debug` を付けて開くと、帯に、解析結果の表示とレイアウト検出の操作が出て、確認用の枠が表示されました(2 ページ分で、枠の数 46)。

### 未確認

- `?debug` を付けた画面で、レイアウト検出を有効と無効に切り替える操作。
- レイアウト検出のモデルを初めて取得するときの、進み具合の表示(モデルは、すでにブラウザに保存してあります)。
- 幅の狭い画面での折り返し。

## 5. 注意点・残課題

- `?debug` を付けない画面では、レイアウト検出を無効に戻す操作と、実行の方法を選ぶ操作がありません。
- 以前のノートと、README の一部の節(`note/009_pdf-view.md` など)は、確認用の枠が初めから見える前提で書いてあります。枠を見るには、URL に `?debug` を付けます。
