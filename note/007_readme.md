## 3. 設計判断

- 未実装の機能を、動くものとして書かないようにしました。冒頭で「PDF を開いて訳文を表示する機能は、まだありません」と明示し、「現在の状態」の表で、実装してあるもの、動くことを確かめたもの、確かめていないこと、まだ無いものを分けています。アプリの目的だけを読んだ人が、いま使えるものと誤解するのを防ぐためです。
- セットアップの手順は、Web アプリの表示(手順 1 と手順 2)を先に、llama.cpp の導入と llama-server の起動(手順 3 と手順 4)を後に置きました。いまの Web アプリは翻訳を呼び出さないので、後半の手順が要るのは、実験用のコマンドを実物の llama-server に対して実行する場合だけです。後半の手順は実行できていないことも、手順の前に書いています。
- 手順とコマンドは、コードを読んで書き、実行できるものは実行して確かめました。
- 外部の事実(モデルのファイルの大きさ、評価値、ライセンスの条件、llama.cpp の版と保存場所)には出典を付け、末尾に一覧を置きました。
- モデルの大きさの表には、既定の量子化の種類(Q4_K_M)での評価値を載せました。計画に書いた評価値は量子化していないモデルのもので、このアプリが実際に動かすファイルの値とは異なるためです。2B と 8B の差は、計画の 0.0058 に対して、Q4_K_M では 0.0038 です。
- Node.js の版の条件は、`package.json` の指定(22.18 以上)と、Vitest 5.1.0 の対応範囲(`^22.12.0 || ^24.0.0 || >=26.0.0`)を合わせて、「22 系(22.18 以上)、24 系、26 以上」と書きました。`package.json` の指定だけでは、Vitest が対象にしていない 23 系と 25 系も含まれるためです。
- ライセンスの条件は、モデルカードの説明の要約にとどめ、本文へのリンクを置きました。条文の解釈は書いていません。
- 「Built with PLaMo」の表記を入れました。ライセンスの第 4 条がこの表記を求めるのは、モデルを第三者に提供する場合です。このリポジトリはモデルのファイルを含まないので、義務には当たらないと私は読みましたが、計画どおり表記しています。
- テストの件数のように、機能の追加で変わる数は README に書いていません。
- コマンドを入力するアプリの呼び名は「ターミナル」にしました。`note/005_probe-speed.md` では「端末」と書いていますが、README では macOS のアプリの名前に合わせています。
- 計画では README を最後の段階で書く予定でしたが、先に作りました。以後は、機能を追加するたびに「現在の状態」「今後の予定」「コマンドの一覧」を更新します。

README を書く過程で、コードについて次の点に気づきました。
今回は README だけを対象にしたため、コードは直していません。

- `src/translate/llamaServer.ts` の `info()` は、応答が JSON でない場合の失敗を `LlamaServerError` にしていません。そのため、別のソフトが HTML を返すと、短い案内ではなく `SyntaxError` と呼び出し履歴が表示されます。
- `package.json` の `engines`(22.18 以上)は、Vitest 5.1.0 の対応範囲より広く、23 系と 25 系を含みます。
- スクリプトの冒頭の使い方に載っていない指定があります。`scripts/mock-llama-server.ts` の `--slots`、`--delay`、`--drop-every` と、`scripts/probe-speed.ts` の `--sentences-per-paragraph` です。
- `scripts/lib/llamaArgs.ts` のコメントは、モデルの保存先を「llama.cpp のキャッシュ」と書いています。llama.cpp 1.0.0 のソースコードでは、保存先は Hugging Face の共有のキャッシュ(既定では `~/.cache/huggingface/hub`)です。
