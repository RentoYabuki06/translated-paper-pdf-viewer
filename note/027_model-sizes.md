# 027 モデルの大きさごとの速度とメモリの測定

## 1. 目的

PLaMo 3 Translate には、4 種類の大きさ(`0.8b`、`2b`、`8b`、`31b`)があります。
これまでは、既定の `2b` でだけ、生成の速度を測っていました。
計画では、`2b` と `8b` の速度を比べて、既定のモデルを決めることにしていました(計画の「決めるべきこと」の 1)。
`2b` 以外のモデルの速度と、メモリの使用量を測り、既定の大きさを見直します。
README の「今後の予定」に残っていた、最後の項目です。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `README.md` | 「モデルの大きさと起動時の指定」に、3 つの大きさの速度、メモリの使用量、論文 1 本の翻訳時間を追加。「必要なもの」にメモリの目安を追加。「現在の状態」と「今後の予定」を更新 |

測定に使ったコマンドは、どれも、すでにあるものです(`npm run model`、`npm run probe:speed`、`npm run probe:placeholders`、`npm run probe:glossary`、`npm run probe:context`)。

## 3. 設計判断

### 測り方

- 測ったのは、`0.8b`、`2b`、`8b` の 3 つです。量子化の種類は、どれも既定の Q4_K_M です。
- `0.8b`(0.57 GB)と `8b`(5.28 GB)のモデルは、利用者の許可を得て、Hugging Face から取得しました。
- `31b`(19.53 GB)は、測っていません。ファイルの大きさ(18,622 MiB)が、このパソコンで llama.cpp が GPU に使えると報告するメモリ(18,186 MiB)を超えます。
- llama-server は、8082 番で、1 つずつ起動しました。指定は、`npm run model -- <大きさ> --port 8082 --dry-run` が表示するコマンドと同じで、記録を詳しくする指定(`-lv 4`)だけを足しました。同時に処理する数は 4、1 件の依頼で使える長さは 2,048 トークンです。
- `2b` も、同じ手順で測り直しました。以前の測定(`note/008_paste-translate-screen.md`)と、同じ条件で比べるためです。
- メモリの使用量は、llama-server が記録する「メモリの内訳」から読みました。`-lv 4` を付けると、起動時と終了時に、GPU の側と、それ以外(Host)の側のそれぞれについて、モデル、文脈、計算用の領域の大きさが記録されます。
- macOS の `footprint` コマンドの値も記録しました。ただし、この値には、モデルのファイルの分が入りません。モデルは、ファイルをメモリに対応づける方法で読み込まれ、`footprint` では「mapped file」という別の項目に数えられます。`footprint` の値だけを見ると、使用量を小さく見積もることになります。
- 論文 1 本の翻訳時間は、ブラウザで測りました。先に `2b` の保存した訳文でレイアウト検出まで済ませ、そのあとで依頼先を切り替えて、「この PDF を翻訳する」を押してから訳し終えるまでを測りました。3 つの大きさで、レイアウト検出の時間が入らない、同じ条件にするためです。

### 既定の大きさ

- 既定は、`2b` のままにします。
- `8b` は、`2b` に比べて、PFN の評価値(PFTB)が 0.0038 高い一方で、論文 1 本の翻訳に 4.5 倍の時間(184.7 秒と 40.8 秒)がかかり、メモリを 2.6 倍(5,713 MiB と 2,225 MiB)使います。
- `8b` は、同時に依頼しても、速度がほとんど上がりませんでした。依頼を 1 件ずつ送った場合に対する、同時に 4 件送った場合の速度は、`2b` が 2.7 倍、`8b` が 1.5 倍です。このアプリは、同時に 4 件を依頼して、訳文を早く出す作りです。
- `0.8b` は、`2b` の 3 分の 1 ほどの時間(14.0 秒)で訳し終えますが、評価値が 0.0230 低くなります。
- 訳文の良し悪しは、この測定では比べていません。既定を変えるだけの根拠は、得られていません。
- この判断は、計画の推奨(「2B を既定にし、実測を見て見直す」)のとおりです。`8b` の訳文を読んで、`2b` より良いと感じる場合は、`npm run model -- 8b` で切り替えられます。

## 4. 動作確認

環境は、macOS 26.6(Apple M5、メモリ 24 GB)、Node.js 26.13.1、Chrome 157、llama.cpp 1.0.0 です。
測定は、2026-11-17 に行いました。それぞれ 1 回です。
測定のあいだ、ほかに、利用者の llama-server(8081 番、`2b`、依頼なし)、Ollama、Chrome、OrbStack が動いていました。

- `npm test`: 440 件すべて成功。
- `npm run build`: 成功。

### 生成の速度

`npm run probe:speed -- --base-url http://127.0.0.1:8082` の結果です。
英語の段落 20 件(合計 1,391 語)を、同時に依頼する数を変えて、3 回訳させます。

| モデル | 生成トークン | 同時 1 件(秒) | 同時 2 件(秒) | 同時 4 件(秒) | 同時 1 件(トークン毎秒) | 同時 2 件(トークン毎秒) | 同時 4 件(トークン毎秒) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `0.8b` | 2,172 | 11.1 | 9.3 | 4.2 | 196.5 | 234.5 | 513.1 |
| `2b` | 2,159 | 33.4 | 25.0 | 12.6 | 64.7 | 86.4 | 171.8 |
| `8b` | 2,164 | 98.5 | 91.0 | 63.6 | 22.0 | 23.8 | 34.0 |

- どの回も、長さの上限で止まった訳文は、0 件でした。
- `2b` の値は、以前の測定(65.4、87.6、173.8 トークン毎秒)と、2% 以内の差でした。
- `0.8b` は、2 回測りました。1 回目は、電源につないでいない状態で、203.1、237.9、517.7 トークン毎秒でした。表の値は、電源につないだ状態で測り直した 2 回目のものです。差は 4% 以内でした。`2b` と `8b` は、電源につないだ状態で測りました。

### メモリの使用量

llama-server が終了時に記録した、メモリの内訳です。単位は MiB です。

| モデル | GPU の側の合計 | うち、モデル | うち、文脈 | うち、計算用 | Host の側の合計 | 合わせた値 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `0.8b` | 576 | 455 | 64 | 56 | 104 | 680(0.71 GB) |
| `2b` | 2,054 | 1,573 | 384 | 96 | 171 | 2,225(2.33 GB) |
| `8b` | 5,441 | 4,797 | 512 | 132 | 272 | 5,713(5.99 GB) |

- 「文脈」は、同時に処理する 4 件分(それぞれ 2,048 トークン)の領域です。
- llama.cpp は、このパソコンで GPU に使えるメモリを、18,186 MiB と報告しました。
- macOS の `footprint` コマンドが報告した値(依頼を処理したあと)は、`0.8b` が 189 から 219 MB、`2b` が 572 MB、`8b` が 648 から 713 MB でした。このほかに、「mapped file」として、`0.8b` で 566 から 567 MB、`2b` で 1,356 MB、`8b` で 4,730 から 4,765 MB が数えられていました。
- 利用者の llama-server(`2b`、起動から 38 時間後)では、`footprint` の値は 527 から 562 MB でした。

### モデルの読み込み

llama-server の記録から読んだ値です。

| モデル | パラメータの数 | 層の数 | 起動から、依頼を受け付けるまでの時間 |
| --- | ---: | ---: | ---: |
| `0.8b` | 8.9 億 | 16 | 19 秒(取得を含む) |
| `2b` | 28.8 億 | 24 | 3 秒(取得済み) |
| `8b` | 85.3 億 | 32 | 132 秒(取得を含む) |

### 数式の目印と、用語集

| モデル | 目印がそろった文(60 文) | 用語集の指定どおりになった件(40 件) | 原文に出てこない語を渡して、訳語が混ざった件(4 件) |
| --- | ---: | ---: | ---: |
| `0.8b` | 60 | 34 | 0 |
| `2b` | 60 | 36 | 0 |
| `8b` | 60 | 35 | 0 |

- 目印は、`npm run probe:placeholders -- --formats bare` の結果です。アプリが使っている書式(`<m1>` など)だけを測りました。
- 用語集は、`npm run probe:glossary` の結果です。略語を日本語の名前に置き換える指定は、どの大きさでも、ほとんど効きませんでした(4 件のうち、`0.8b` が 0 件、`2b` と `8b` が 1 件)。

### 論文 1 本の翻訳(arXiv 1706.03762、104 段落)

| モデル | 依頼 | 時間(秒) | 失敗 | 原文のまま残った段落 | 文ごとに訳し直した段落 | `2b` と同じ訳文の段落 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `0.8b` | 107 | 14.0 | 0 | 0 | 1 | 20 |
| `2b` | 104 | 40.8 | 0 | 0 | 0 | — |
| `8b` | 104 | 184.7 | 0 | 0 | 0 | 25 |

- 「翻訳サーバー」の画面で、依頼先を 8082 番に切り替えると、モデルの名前は、`plamo-3-translate-0.8b-Q4_K_M`、`plamo-3-translate-8b-Q4_K_M` と表示されました。注意は、表示されませんでした。
- `2b` の行は、`note/026_model-alias.md` の確認で測った値です(同じ日、同じ手順)。
- `0.8b` の依頼が 107 件なのは、1 段落が、文ごとの訳し直し(3 件の依頼)になったためです。
- 訳文が、元の段落の範囲に収まらずに末尾が隠れた段落は、`0.8b` と `8b` のどちらも 0 件でした。
- 訳文の文字数の合計は、`0.8b` が 12,056、`2b` が 12,218、`8b` が 12,251 でした。
- 訳語の選び方は、大きさによって少し違いました。訳文の全体で、「アテンション」は `0.8b` が 81 回、`2b` が 76 回、`8b` が 80 回、「注意」は 12 回、15 回、8 回でした。

### 保存した訳文が、大きさごとに分かれること

`note/026_model-alias.md` で未確認だった点です。

- `8b` で翻訳したときは、依頼 104 件、再利用 0 件でした。`2b` で保存してあった訳文は、使われませんでした。
- そのあと、依頼先を `2b`(8081 番)に戻して翻訳すると、依頼 0 件、再利用 104 件で、104 段落すべてが、もとの `2b` の訳文と一字一句同じでした。`8b` の訳文とは、79 段落が違いました。

### 文脈の実験での訳文の違い

`npm run probe:context` の文章(この実験のために書き起こしたもの。`note/016_probe-context.md`)での、訳文の違いの例です。
文脈は、アプリと同じ渡し方(`labeled`)です。

| 原文 | `0.8b` | `2b` | `8b` |
| --- | --- | --- | --- |
| 見出し "2 Nets" | 2 ネット | 2 ネットワーク | 2 ネットワーク |
| 見出し "3 Training" | 3 学習 | 3 学習 | 3 学習 |
| "Each head keeps its own net, …" の "net" | ネット | ネットワーク | ネットワーク |

- この文章では、"net" を「点の有限集合」の意味で使っています。`2b` と `8b` は、見出しと最後の段落で「ネットワーク」と訳しました。`0.8b` は、「ネット」と訳しました。
- 数式の目印は、3 つの大きさとも、10 項目すべてでそろいました。
- この 10 項目だけで、訳文の質の差は、判断できません。

### 測定のあいだに起きたこと

- `0.8b` の 1 回目の測定の途中(12 時 50 分 46 秒)で、パソコンがスリープに入りました(`pmset -g log` の記録)。速度の測定と、目印の実験は、その前に終わっていました。用語集の実験と、文脈の実験は、スリープと重なりました。この 2 つは、時間を使わず、訳文だけを使うので、結果はそのまま採用しました。
- `2b`、`8b`、`0.8b` の 2 回目の測定と、ブラウザでの測定は、スリープと重なっていません。

### 確認でパソコンに残したもの

- 取得したモデルのファイルは、`~/.cache/huggingface/hub` に残しています。`models--pfnet--plamo-3-translate-0.8b-GGUF`(0.57 GB)と、`models--pfnet--plamo-3-translate-8b-GGUF`(5.28 GB)です。
- 測定用に起動した llama-server(8082 番)は、止めました。
- ブラウザには、`0.8b` と `8b` で訳した arXiv 1706.03762 の訳文が、保存されたままです。設定は、確認の前の内容(8081 番)に戻しました。

## 5. 注意点・残課題

- 測定は、開発に使っているパソコン 1 台での、1 回ずつの値です。ほかのパソコンでは、速度も、GPU に使えるメモリも変わります。
- メモリの使用量は、llama-server 自身が記録した値です。macOS が報告する値とは、数え方が違います。
- `8b` を使う場合は、利用者の llama-server を止めて、`npm run model -- 8b --port 8081` で起動し直します。訳文は、モデルの大きさごとに分けて保存されます。
