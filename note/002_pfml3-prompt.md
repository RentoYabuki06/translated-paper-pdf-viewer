# 002 PFML3 の組み立て

## 1. 目的

PLaMo 3 Translate は、PFML3 という決まった書式の入力だけを受け付けます。
翻訳の依頼ごとに、原文・訳先の言語・文脈・用語集・履歴・文体から、この書式の文字列を組み立てる処理が必要です。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `src/translate/pfml3.ts` | `buildPfml3Prompt`(書式の組み立て)、`neutralizeSpecialTokens`(本文中の特殊トークン文字列の無効化)、`cleanPfml3Output`(出力の末尾に残った終了トークンの除去) |
| `tests/translate/pfml3.test.ts` | 上記 3 つの関数の単体テスト 17 件 |

要素の並びは、モデルカードの記述に合わせました: `dataset`、`context`、履歴の `input` と `output` の組、`glossary`、今回の `input`、`output`。

## 3. 設計判断

- 書式は自分で組み立てます。チャット用の書式(`chat_template`)には任せません。PFN がアプリへの組み込みで推奨している方法であり、文脈と用語集の配置を自分で制御できるためです。
- 文頭のトークン(`<|plamo:bos|>`)は付けません。llama.cpp が自動で付けるためです。
- 本文に含まれる `<|plamo:` という文字列は、`<` と `|` の間にゼロ幅スペースを挟んで無効化します。PDF から取り出した文章は信頼できない入力であり、区切りの文字列が混ざると依頼の構造を書き換えられるためです。文字列を削除する方法は、原文の情報を失うので選びませんでした。
- 文体(`form`)は、訳先が日本語のときだけ受け付け、それ以外ではエラーにします。モデルカードが、文体は日本語への翻訳でだけ使えると定めているためです。
- 履歴の `output` には文体を書きません。モデルカードが、文体と用語集は今回の訳文にだけ適用されると述べているためです。

## 5. 注意点・残課題

- 「履歴の `output` に文体を書かない」ことと「原文の言語を省略した履歴の `input` に言語を書かない」ことは、モデルカードに明示的な例がありません。記述からの解釈で実装しています。実際のモデルで確かめる必要があります。
- ゼロ幅スペースによる無効化が、llama.cpp の字句分割で意図どおりに働くことは未確認です。
