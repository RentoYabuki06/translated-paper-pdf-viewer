# 033 PDF を開いたら自動で翻訳を始め、原文を並べる操作をスイッチにする

## 1. 目的

利用者から、次の 2 点の依頼がありました。

- 「この PDF を翻訳する」のボタンは不要。PDF を開いたら、自動で翻訳を始める。
- 「原文を左に並べる」は、チェックボックスではなく、トグルスイッチにする。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `src/viewer/PdfViewer.tsx` | PDF を開いたときに、翻訳を始める処理を呼ぶ。翻訳を始めるボタンは、やり直す理由があるときだけ出す。「原文を左に並べる」をスイッチにした |
| `src/index.css` | スイッチの見た目 |
| `README.md` | 「PDF を翻訳する」の手順と、用語集、訳文の保存の説明を、新しい画面に合わせた |

## 3. 設計判断

- 翻訳は、開いた PDF が替わったときに、1 回だけ始めます。同じ PDF で 2 度始めないよう、始めた PDF を覚えています(開発時の React は、同じ処理を 2 回呼ぶことがあります)。
- ボタンを完全には無くしませんでした。次の場合は、利用者が翻訳を始め直す手段が要るためです。ボタンは、この場合にだけ出ます。

  | 場合 | ボタンの名前 |
  | --- | --- |
  | 翻訳サーバーに接続できなかった、または、レイアウト検出を始められなかった | 翻訳を再開 |
  | 「中止」を押した | 翻訳を再開 |
  | 翻訳したあとで、用語集が変わった | 訳し直す |

- URL に `?debug` を付けた画面では、翻訳を自動で始めません。この画面は、翻訳の前の解析結果を確かめるためのもので、翻訳を始めると、確認用の枠が消えるためです。この画面では、以前と同じ「この PDF を翻訳する」のボタンを出します。
- スイッチは、チェックボックスの要素のまま、見た目だけを変えました(`role="switch"`)。キーボードでの操作と、読み上げは、チェックボックスと同じに働きます。
- 「訳文を表示」は、チェックボックスのままです。依頼は「原文を左に並べる」だけでした。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Chrome 157 です。`npm run dev` のページで確かめました。

- `npm test`: 472 件すべて成功。
- `npm run build`: 成功。
- `?arxiv=1706.03762` を付けて開くと、ボタンを押さずに翻訳が始まり、「翻訳が終わりました: 104 / 104 段落」と表示されました(訳文は、保存してあるものです)。帯のボタンは、用語集、訳文の比較、PDF として保存の 3 つでした。
- スイッチを押すと、原文と訳文が並び(1 行に 2 ページ)、スイッチの色が変わりました。
- 依頼先の URL を、何も起動していないポートに変えて開くと、接続できない知らせと、「翻訳を再開」のボタンが出ました。確認のあと、依頼先の URL は、もとに戻しました。

### 未確認

- ファイルの選択と、ドラッグ&ドロップで開いたときの、自動の開始(arXiv から開く場合と同じ処理を通ります)。
- 「中止」のあとの「翻訳を再開」と、用語集を変えたあとの「訳し直す」。
- 保存してある訳文が無い PDF で、翻訳の依頼が実際に走ること。
- レイアウト検出のモデルを、初めて取得する場合。

## 5. 注意点・残課題

- PDF を開くだけで、翻訳サーバーへの依頼が始まります。初めて使うブラウザでは、レイアウト検出のモデル(130.5 MB)の取得も、開いたときに始まります。
- 翻訳したあとで依頼先(モデル)を切り替えても、訳し直すボタンは出ません。PDF を開き直すと、切り替えた先で翻訳されます。
- README の測定の記述には、「この PDF を翻訳する」を押してからの時間、という書き方が残っています。測ったときの手順なので、そのままにしました。
