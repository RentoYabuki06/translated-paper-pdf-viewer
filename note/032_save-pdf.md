# 032 印刷の画面を使わずに、PDF のファイルを保存する

## 1. 目的

`note/030_print.md` では、ブラウザの印刷の画面を開き、送信先に「PDF に保存」を選んでもらう作りにしました。
利用者から、印刷の機能は無くして、ボタンを押すと PDF が保存されるだけにしたい、という依頼がありました。
ボタンは、プリンターの形のアイコンにします。

## 3. 設計判断

### PDF を、アプリの中で作る

- ブラウザのページからは、印刷の画面を出さずに「PDF に保存」を実行することができません。`window.print()` は、必ず印刷の画面を開きます。
- そこで、PDF のファイルを、アプリの中で作ります。ページを 1 枚ずつ画像にして、その画像を 1 ページに 1 枚置いた PDF にします。
- この方法では、保存した PDF の文字は画像になります。文字の選択と検索はできません。印刷の画面を使う方法では、文字は文字のまま入りました。ここは、以前より劣る点です。
- 文字のまま入れる方法は、選びませんでした。日本語のフォントを PDF に埋め込む処理と、訳文の行の折り返しを PDF の上でやり直す処理が要り、画面の表示と同じ見た目にするのが難しいためです。

### ページを画像に描き写す方法

- ページは、PDF.js が描いた canvas に、訳文の要素(HTML)を重ねて表示しています。canvas は、そのまま画像に写せますが、HTML の要素は写せません。
- 訳文は、ブラウザが決めた 1 文字ごとの位置を読み取り(`Range.getClientRects`)、同じ位置に、同じフォントで描きます。行の折り返しや両端そろえを、自分で計算し直さないので、画面の表示と同じ位置になります。
- 訳文の中の数式は、要素に付いている背景の画像の指定(画像、大きさ、位置)を読み取り、同じ範囲を描きます。
- 元の文字を消す描画は、画面と同じ範囲(`clip-path` の指定)だけに描きます。
- 選ばなかった方法は、HTML を画像にするライブラリ(html2canvas など)を足す方法です。必要な要素は、文字と数式の 2 種類だけなので、ライブラリを足さずに済ませました。
- 翻訳の途中の印(薄い青の点滅など)と、収まらなかった訳文の「…」の印は、描きません。

### PDF のファイルの作り方

- JPEG のデータは、圧縮し直さずに、そのまま PDF に入れます(DCTDecode)。PDF の形は単純なので、ライブラリを足さずに、自分で書きました。
- JPEG の品質は 0.9 です。
- ページの大きさは、もとの PDF のページの大きさ(ポイント)です。並べた形では、幅が 2 ページ分になります。
- 画像の細かさは、画面に描いた canvas と同じです。倍率を上げて保存すると、細かくなり、ファイルも大きくなります。
- ファイルの名前は、もとの名前に、訳文だけなら `_ja`、並べた形なら `_en-ja` を足したものです。名前に使えない記号(`:` など)は、`_` に替えます。

環境は、macOS 26.6(Apple M5)、Chrome 157 です。`npm run dev` のページで確かめました。

- `npm test`: 472 件すべて成功。
- `npm run build`: 成功。

ファイルの保存の直前(ダウンロード用のリンクを押す処理)を差し替えて、作られた PDF のデータを受け取り、そのデータを、このアプリで開き直しました。

## 5. 注意点・残課題

- 保存した PDF の文字は、選択も検索もできません。
- ファイルは、もとの PDF より大きくなります(上の表を参照)。
- 紙に刷る手段は、アプリの中にはありません。保存した PDF を、ほかのソフトで開いて刷ります。
- 訳文の文字の縦の位置は、フォントの上の高さと下の高さの比から求めています。訳文のフォントに無い文字(別のフォントで代わりに表示される文字)は、縦の位置が少しずれる可能性があります。
