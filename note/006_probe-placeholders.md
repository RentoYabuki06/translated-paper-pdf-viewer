# 006 数式の目印が訳文に残る割合の実験スクリプト

## 1. 目的

このアプリは、文中の数式を目印(タグ)に置き換えてから訳し、訳文中の目印の位置に元の数式の画像を戻します。
PLaMo 3 Translate が目印を訳文に残すかどうかは、公式の資料に書かれていません。
目印の書式の候補を比べ、採用する書式を決めるための測定を、1 コマンドで行えるようにします。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `scripts/probe-placeholders.ts` | 実験の本体。数式を含む文 60 件を書式ごとに訳させ、合格した文の割合を表にする |
| `scripts/lib/placeholderFormats.ts` | 書式 4 種類の定義、原文への目印の埋め込み(`encodeSentence`)、訳文の検査(`checkTranslation`)、表記ゆれの修正(`normalizeTags`) |
| `tests/scripts/placeholderFormats.test.ts` | 上記の単体テスト 23 件 |
| `scripts/mock-llama-server.ts` | 指定 `--drop-every N` を追加。N 件に 1 件の依頼で、訳文から目印を 1 つ落とす |
| `package.json` | コマンド `probe:placeholders` を追加 |

書式の候補は次の 4 種類です。

| 名前 | 内容 | 原文の例 |
| --- | --- | --- |
| `bare` | 番号だけの目印 | `Let <m1> denote ...` |
| `paired` | 数式の文字を包む、対の目印 | `Let <m1>xi ∈ Rd</m1> denote ...` |
| `bare+pin` | `bare` に、用語集で「目印はそのまま残す」という指定を足したもの | 原文は `bare` と同じ |
| `paired+pin` | `paired` に、同じ指定を足したもの | 原文は `paired` と同じ |

合格の条件は、「すべての目印が、ちょうど 1 回ずつ、正しい形で訳文に残ること」です。
対の書式では、開く側と閉じる側がそろい、順番が正しく、目印どうしが入れ子や交差になっていないことも条件に含みます。

出力される表の列の意味は次のとおりです。

- 厳密に合格: 訳文をそのまま検査して合格した文の数。
- 表記を直して合格: 目印の表記ゆれ(全角の山括弧、内側の空白、大文字)を直してから検査して合格した文の数。
- 上限で停止: 生成の上限に達して、訳文が途中で切れた文の数。

## 3. 設計判断

- 書式の候補は、先行例の方式から選びました。番号だけの目印は Sakutto の PDF リーダー、対の目印は kiskyk/plamo-translate、用語集による固定は Sakutto の Web ページ翻訳が使っている方式です。どれも考え方だけを参考にし、コードは写していません。
- 検査は「厳密」と「表記を直してから」の 2 通りで行います。モデルが目印を全角で出すなどの表記ゆれは、アプリ側で直せば救えるためです。2 つの差が、直す処理の効果を表します。
- 目印の名前は `m` と番号にしました(`<m1>`)。HTML に実在する要素名と重ならない、短い名前にするためです。
- 数式の文字に含まれる山括弧(不等号)は、別の文字に置き換えます。対の目印の内側に `<` があると、目印の切れ目を誤って読むためです。対の目印の内側の文字は、訳文を表示するときに元の数式の画像に置き換わるので、文字を変えても表示には影響しません。
- この処理は `scripts/lib/` に置き、アプリ本体(`src/`)には入れていません。実験で 1 つの書式を選んだあとに、選んだ書式だけを本体に実装するためです。

## 4. 動作確認

- `npm test`: 80 件すべて成功(本機能の 23 件と、既存の 57 件)。
- `npm run build`: 成功。
- 模擬サーバー(目印をすべて残す)に対する `npm run probe:placeholders`: 4 書式とも 60 件中 60 件が合格と表示。数式は合計 133 か所。
- 模擬サーバー(7 件に 1 件で目印を 1 つ落とす)に対する実行: `bare` は 60 件中 52 件、`paired` は 60 件中 51 件が合格と表示。不合格の文について、原文、訳文、欠けた目印の番号を表示。
- 書式名の指定が誤っている場合: 1 行の案内を表示し、終了コード 1 で終了。
- 実物の llama-server に対する測定: 未実施。llama.cpp が未導入のためです。

## 5. 注意点・残課題

- 上記の合格数は、模擬サーバーに対するものです。PLaMo 3 Translate が実際に目印を残す割合は、まだ分かっていません。
- 実験用の文は自作のため、実際の論文の文より素直な構文に偏っている可能性があります。
- この実験が調べるのは、目印が残るかどうかだけです。目印の位置が訳文として自然かどうか、訳の質が書式によって変わるかどうかは、訳文を読んで確かめる必要があります。
- 採用の目安は「厳密に合格、または表記を直して合格が 98% 以上」です。どの書式も届かない場合は、目印がそろわない段落を原文のまま残す方針で進めるか、別の書式を試すかを決めます。
