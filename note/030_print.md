# 030 PDF への保存と印刷、操作の帯の固定をやめる

## 1. 目的

利用者から、2 つの依頼がありました。

- 下へ送ったときに、操作の帯(倍率や翻訳のボタンがある部分)が、画面の上に残り続ける動作は要らない。
- 翻訳した論文だけのものと、元の論文と並べたものの、どちらも、PDF として保存でき、印刷できるようにしたい。

## 2. 変更内容

| ファイル | 内容 |
| --- | --- |
| `src/index.css` | 操作の帯を、画面の上に固定する指定を外した。印刷のときの見た目(ページだけを、1 行につき 1 枚で出す)を追加 |
| `src/viewer/PdfViewer.tsx` | 「PDF に保存・印刷」のボタンを追加。すべてのページの描画を待ってから、ブラウザの印刷の画面を開く |
| `src/viewer/PageView.tsx` | 表示範囲から離れていても描画させる指定と、描画が終わったかどうかの印を追加 |
| `README.md` | 「PDF を翻訳する」の操作の表に、1 行を追加 |

## 3. 設計判断

- PDF への保存は、ブラウザの印刷の機能に任せます。印刷の画面で、送信先に「PDF に保存」を選ぶと、PDF のファイルになります。印刷と、PDF への保存を、1 つの仕組みで済ませられます。
- 選ばなかった方法は、アプリの中で PDF のファイルを組み立てる方法です。PDF を書き出すライブラリが要り、訳文の文字の配置を、画面とは別に作り直すことになります。
- 出力は、いま表示している形に従います。「原文を左に並べる」にチェックが入っていれば、原文と訳文を並べた形、入っていなければ、訳文だけの形です。ボタンを 2 つに分けていません。
- 用紙の大きさは、1 行分(1 ページ、または並べた 2 ページ)の大きさに合わせ、余白を 0 にします。1 行が、ちょうど 1 枚になります。大きさは、1 ページ目の行から決めます。
- ページは、表示範囲の近くだけを描画する作りです。印刷の前に、すべてのページを描画させ、終わるのを待ちます(3 分まで)。
- 数式の切り抜きは、背景の画像として置いています。ブラウザは、既定では背景を印刷しないので、背景も印刷する指定を入れました。
- 訳文の状態を示す枠(訳している最中、失敗、原文のまま)と、確認用の枠は、印刷しません。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Chrome 157 です。

- `npm test`: 467 件すべて成功。`npm run build`: 成功。
- `npm run dev` のページで、arXiv 1706.03762 を開き、保存してある訳文で翻訳を済ませました。
  - 操作の帯の位置の指定は、固定ではなくなっていました(`position` が `static`)。
  - 印刷の画面を開く処理(`window.print`)を、記録するだけの処理に差し替えて、「PDF に保存・印刷」を押しました。印刷の画面は、開くとブラウザの操作が止まるので、確認の道具からは開けないためです。
  - 訳文だけの形: 1.2 秒で、15 ページすべての描画が終わり、用紙の大きさは 918 × 1,188 画素と指定されました。
  - 並べた形: 1.6 秒で、30 ページ分(原文 15、訳文 15)の描画が終わりました。
  - どちらも、処理のあとで、用紙の大きさの指定は取り除かれ、準備中の表示は消えました。

### 未確認

- 実際の印刷の画面での見た目と、保存した PDF の中身。上の理由で、確かめられていません。印刷のときの見た目の指定(ページ以外を隠す、1 行につき 1 枚にする、数式の背景を印刷する)は、画面では確かめていません。
- 紙への印刷。用紙の大きさを、ページの大きさに合わせているので、A4 などの紙に刷るときは、印刷の画面で、用紙に合わせて縮める指定が要る可能性があります。
- ページごとに大きさが違う PDF。
- ページの多い PDF での、準備にかかる時間とメモリ。

## 5. 注意点・残課題

- 保存した PDF の訳文は、文字として入るか、画像として入るかを、確かめていません。原文のページは、画像として描いたものです。
- 訳文が範囲に収まらず、末尾が隠れている段落は、隠れたまま出力されます。
