# 039 README の先頭に、2 回目からの起動のしかたを載せる

## 目的

サーバーをすべて止めたあと、次に使うときに何を起動すればよいかを、README の先頭で分かるようにする。
これまでの README では、起動のコマンドが「セットアップ」の手順 2 と手順 4 に分かれていた。

## 変更内容

- `README.md`: 題名のすぐ下に、節「起動のしかた(セットアップを終えたあと)」を加えた。
  - 起動するコマンド 2 つ(`npm run model` と `npm run dev`)と、開く URL を書いた。
  - Docker や OrbStack が要らないこと、ポート番号を変える場合の指定、起動のときにインターネット接続が要ること、止め方を書いた。
- `README.md`: それまで題名のすぐ下にあった説明に、見出し「このアプリについて」を付けた。文は変えていない。

## 設計判断

- 新しい節は、説明の文より前に置いた。依頼が「一番上」だったためである。
- 説明の文に見出しを付けた。付けないと、説明の文が「起動のしかた」の節の続きに見えるためである。
- コマンドの例は、既定のポート番号(8080 番)のものにした。8081 番を使うのは、開発に使っているパソコンの事情であり、その旨を箇条書きに書いた。

## 動作確認

- 開発に使っているパソコンで、`lsof` と `ps` を使い、次の 3 つを確かめた。
  - llama-server は、OrbStack の中ではなく、パソコンの上のプロセスとして 8081 番で待ち受けている。
  - Web アプリ(Vite)は、パソコンの上のプロセスとして 5173 番で待ち受けている。
  - 8080 番は、OrbStack が使っている。
- `scripts/llama.ts` に、`--port` の指定があることを確かめた。
- `npm run build` が通ることを確かめた。
- 未確認: すべてのサーバーを止めたあとに、この節の手順だけで起動し直す操作。
- 未確認: GitHub の上での README の表示。

## 注意点・残課題

- 「取得済みのモデルのファイルは、取り直しません」は、llama-server の動きについての記述である。この変更では、起動し直して確かめていない。
