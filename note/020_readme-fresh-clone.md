## 3. 設計判断

- 複製は、手元のリポジトリから行いました。README は GitHub からの取得(`git clone https://github.com/…`)を案内していますが、GitHub のリポジトリは非公開で、取得には認証が要ります。手元のリポジトリは push 済みで、内容は同じです。GitHub からの取得そのものは、確かめていません。
- 開発用のサーバーは、すでに 5173 番で起動しているものを止めずに、複製した側を別の番号(5174 番)で起動しました。Vite は、5173 番が使われていると、次の番号を自動で使います。
- 複製した側では、レイアウト検出と翻訳は試していません。ブラウザの保存領域は URL(ポート番号を含む)ごとに分かれるため、複製した側で検出を有効にすると、検出モデル(130.5 MB)をもう一度取得することになるためです。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Node.js 26.13.1、npm 11.20.0、Chrome です。
複製したのは、コミット `5bcb382` の状態です。

| 手順 | 実行したこと | 結果 |
| --- | --- | --- |
| 手順 1 | `npm install` | 成功。`added 68 packages`、脆弱性の報告は 0 件。`npm warn install-scripts` の警告が 2 件(`fsevents`、`protobufjs`) |
| 動作の確認 | `npm test` | 33 ファイル、379 件すべて成功 |
| 動作の確認 | `npm run build` | 成功 |

| 手順 2 | Chrome で開く | 題名、3 つのボタン、接続の状態の表示が出た。コンソールにエラーは無かった |
| コマンドの一覧 | `npm run preview` | `http://localhost:4173/` で起動。応答は HTTP 200。PDF.js と ONNX Runtime Web の付属ファイルも返った |

- 複製した側のページでは、接続の状態が「llama-server(http://127.0.0.1:8080) — 接続できません」になりました。新しい URL では設定が保存されておらず、既定の 8080 番を見に行くためです。この端末では、8080 番を別のソフトが使っています。
- 確認のあと、複製した側で起動した 3 つのサーバー(模擬サーバー、開発用、表示用)を止めました。
