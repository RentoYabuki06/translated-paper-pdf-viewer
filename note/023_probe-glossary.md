# 023 用語集の欄の効き方を確かめる実験

## 1. 目的

段落は 1 つずつ独立に訳すので、同じ語の訳語が段落によって変わることがあります(`note/017_translation-context.md` の残課題)。
PLaMo 3 Translate の入力には、原文の語と訳語の組を渡す「用語集」の欄があります。
この欄をアプリに組み込む前に、次の 3 点を確かめます。

- 訳語の指定が、どのくらい守られるか。複数形、文頭の大文字、複合語の一部、略語など、語の出方によって変わるか。
- 原文に出てこない語を渡すと、訳文がどうなるか。登録した語をすべて渡してよいか、原文に出てくる語だけを選んで渡すかを決めるためです。
- 数式の目印(`<m1>` など)が、用語集を付けても訳文に残るか。

モデルカードは、用語集の書式と置く位置を説明していますが、項目の数の上限、原文に出てこない語を渡した場合の動作、大文字と小文字の扱いは書いていません。
PFN 公式の plamo-translate-cli には、用語集を渡す指定が見つかりませんでした。
この 2 点は、2026-11-17 に、調査を任せた補助のエージェントが出典を読んで報告した内容です。
読んだ範囲は、Hugging Face の `pfnet/plamo-3-translate-2b-GGUF` のモデルカードと、plamo-translate-cli の README、`src/plamo_translate/` の `main.py`、`clients/translate.py`、`servers/mlx/pfml3.py` です。`servers/llama_cpp/` は読んでいません。
そのため、実際に訳させて確かめます。

## 3. 設計判断

- 訳させる文章は、この実験のために書き起こしました。論文からの転載は含みません。
- 指定する訳語は、用語集が無いときに選ばれやすい訳語とは、わざと別のものにしました("attention" に「注意」、"learning rate" に「学習係数」など)。用語集が効いたかどうかを、訳文の文字列から見分けるためです。そのため、訳語として自然でないものを含みます。
- 判定は、文字列の一致で行います。各件に、訳文に含まれているはずの文字列(指定した訳語)と、含まれていてはいけない文字列(用語集が無いときに選ばれやすい訳語)を書いておき、両方を満たした件を「指定どおり」と数えます。
- この判定は、語が出てくる回数を数えません。指定した訳語が 1 回でも入り、避けたい訳語が 1 回も無ければ、「指定どおり」になります。訳語に別の語が足された場合(「注意」が「注意機構」になった場合)も、「指定どおり」に数えます。細かい違いは、表示された訳文を読んで確かめます。
- 用語集を付けない場合の訳文も、同じ基準で判定します。用語集が無くても指定どおりになる件を、区別するためです。
- 原文に出てこない語の件では、渡した訳語が訳文に混ざらなかった件を「指定どおり」と数え、あわせて、訳文が用語集なしと一字一句同じかどうかを表示します。
- 依頼は 1 件ずつ送ります。生成の設定は、毎回、最も確率の高いトークンを選ぶものなので、結果は、依頼の順番や同時に送る数によりません。
- 文脈の欄は使いません。用語集だけの効果を見るためです。アプリ本体は文脈も渡すので、文脈と用語集を両方渡した場合の動作は、アプリに組み込んだあとで、実際の論文で確かめます。
- 依頼先に Ollama も選べるようにしました。アプリは Ollama にも依頼できるので、用語集が同じように効くかを確かめるためです。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Node.js 26.13.1、llama.cpp 1.0.0、Ollama 0.40.16 です。
llama-server は `npm run model -- --port 8081`(モデルは `2b`、Q4_K_M)で起動しました。
Ollama のモデルは、同じファイルを取り込んだ `plamo-3-translate-2b` です(`note/022_ollama-plamo-check.md`)。

- `npm test`: 399 件すべて成功。
- `npm run build`: 成功。
- `npm run probe:glossary -- --base-url http://127.0.0.1:8081`: 44 件を、2 通りずつ訳しました。39 秒かかりました。測定は 1 回です。
- `npm run probe:glossary -- --ollama-model plamo-3-translate-2b`: 同じ 44 件を訳しました。45 秒かかりました。判定は 44 件とも llama-server と同じで、用語集を付けた訳文も 44 件とも一字一句同じでした。
- `npm run probe:glossary -- --kinds foo`: 指定できる種類の一覧を表示して、終了コード 1 で終わりました。
- llama-server が無い URL を指定した場合: 接続できないことを表示して、終了コード 1 で終わりました。
- 模擬サーバー(`npm run mock`)に対して、`--kinds basic,absent` で実行: 12 件の訳文と表が表示されました。模擬サーバーは訳さないので、「指定どおり」の数に意味はありません。

### 数えた結果(llama-server)

| 語の出方 | 件数 | 用語集なしで指定どおり | 用語集ありで指定どおり | 目印がそろった件数 |
| --- | ---: | ---: | ---: | ---: |
| 登録した形のまま出てくる語(`basic`) | 8 | 0 | 8 | 8 |
| 大文字と小文字が違う語(`case`) | 4 | 0 | 4 | 4 |
| 複数形や活用形(`inflected`) | 5 | 0 | 5 | 5 |
| 複合語の一部、表記の違い(`compound`) | 5 | 0 | 4 | 5 |
| 略語(`acronym`) | 4 | 0 | 1 | 4 |
| 英語のまま残す語(`keep`) | 3 | 0 | 3 | 3 |
| 数式の目印と一緒に出てくる語(`math`) | 4 | 0 | 4 | 4 |
| 長い語と、その一部である短い語(`overlap`) | 5 | 1 | 5 | 5 |
| 長い段落に何度も出てくる語(`long`) | 2 | 0 | 2 | 2 |
| 原文に出てこない語(`absent`) | 4 | — | 4 | 4 |

- 原文に出てくる語を渡した 40 件のうち、指定どおりの訳文になったのは 36 件でした。用語集を付けない場合は 1 件でした。
- 数式の目印は、44 件すべてで、訳文にちょうど 1 回ずつ残りました(目印を含む件は 4 件です)。
- 原文に出てこない語を渡した 4 件では、渡した訳語が訳文に混ざった件はありませんでした。ただし、訳文が用語集なしと一字一句同じだったのは 1 件だけで、3 件は言い回しが変わりました。
- 入力のトークンは、用語集の 1 項目につき 7 から 12 増えました。20 項目を渡した件では、137 増えました(38 から 175)。

### 指定どおりにならなかった 4 件

| 種類 | 原文の語と、指定した訳語 | 用語集を付けた訳文 |
| --- | --- | --- |
| `compound` | "attention" に「注意機構」。原文は "Self-attention"(2 回)と "encoder-decoder attention" | 「セルフアテンション」「エンコーダ・デコーダアテンション」のまま |
| `acronym` | "RNN" に「再帰型ニューラルネットワーク」 | 「RNN」のまま |
| `acronym` | "SGD" に「確率的勾配降下法」 | 「SGD」のまま。訳文は、用語集なしと一字一句同じ |
| `acronym` | "LSTM" に「長・短期記憶」 | 1 回目は「長・短期記憶(LSTM)」、2 回目は「LSTM」 |

- 略語を日本語の名前に置き換える指定は、3 件とも、指定どおりになりませんでした。略語に語を足す指定("BLEU" に「BLEU 値」)は、2 回のうち 1 回目に効きました。
- 複合語の一部になっている語は、効く場合と効かない場合がありました。"encoder-decoder attention" だけが出てくる文では「エンコーダ・デコーダ注意機構」になり、"Multi-head attention" は「マルチヘッド注意」になりました。"Self-attention" が先に 2 回出てくる文では、効きませんでした。

### 指定どおりの件で、読んで分かったこと

- 複数形("residual connections"、"Nets"、"queries"、"embeddings")と、動詞の活用形("fine-tuned"、"fine-tuning")には、単数形や原形で登録した訳語が使われました。
- 文頭の大文字("Attention")、語頭が大文字の見出し("Residual Connections")、すべて大文字の見出し("RELATED WORK")にも、小文字で登録した訳語が使われました。
- 原文ではハイフンでつながり、用語集では空白で区切った語("self-attention" に対する "self attention"、"learning-rate" に対する "learning rate")にも、訳語が使われました。
- 訳語に、別の語が足されることがありました。"attention" に「注意」を指定した長い段落では、6 回のうち 3 回が「注意」、3 回が「注意機構」でした。用語集のほうを "Attention" と大文字で始めた件では、2 回とも「注意機構」になりました。
- 訳語が、文に合わせて変えられることがありました。"batch size" に「ミニバッチの大きさ」を指定した段落で、"A larger batch size" は「ミニバッチを大きくしても」と訳されました。
- 長い語と、その一部である短い語の両方を渡した 5 件では、長い語には長い語の訳語が使われました。短い語が、長い語の一部としてしか原文に出てこない 3 件("self-attention" と "attention" など)で、短い語の訳語が混ざった件はありませんでした。
- 英語のまま残す指定("dropout" に "dropout" など)は、3 件とも効きました。

### 決めたこと

- アプリ本体には、用語集を組み込みます。40 件のうち 36 件で指定どおりになり、数式の目印も失われなかったためです。
- 依頼には、登録した語のうち、その段落の原文に出てくる語だけを渡します。理由は 2 つです。原文に出てこない語を渡すと、訳語は混ざらないものの、4 件のうち 3 件で訳文の言い回しが変わりました。また、渡した項目の数だけ、入力が長くなります。
- 原文に出てくるかどうかは、大文字と小文字、複数形、ハイフンと空白の違いを区別せずに判定します。モデルが、これらの違いがあっても訳語を使ったためです。
- 渡す語は、登録した形のままにします。原文に出てきた形(複数形など)に直さなくても、訳語が使われたためです。
- 用語集の指定は、必ず守られるものではないことを、画面と README に書きます。

### 未確認

- 実際の論文での効果。この実験の文章は、見出しと、1 文から 8 文の文章です。
- 文脈の欄と一緒に渡した場合。
- 語が出てくる回数ごとの、訳語が使われた割合。この実験は、訳語が 1 回でも入ったかどうかで判定しています。
- 用語集の項目の順番を変えた場合。試しに 20 項目の順番を逆にした 1 件では、訳文は同じでした(この実験のコマンドには含めていません)。
- `2b` 以外のモデル。
- 文体を「です・ます調」にした場合。
- 日本語から英語への翻訳。

## 5. 注意点・残課題

- この実験が示すのは、44 件の文章での結果です。訳文の質を、数値で比べたものではありません。
- 判定は文字列の一致なので、指定した訳語が、別の語の一部として入った場合も「指定どおり」に数えます。実験用の文章では、避けたい文字列が、含まれているはずの文字列の一部にならないことを、テストで確かめています。
- 略語を日本語の名前に置き換える指定は、この実験では効きませんでした。略語の訳語をそろえたい場合の手段は、用意していません。
