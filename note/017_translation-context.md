# 017 翻訳の依頼に、文脈を付ける

## 1. 目的

段落を 1 つずつ独立に訳すと、分野や話の流れが分からないために、訳語を誤ることがあります。
`note/016_probe-context.md` の実験で、PLaMo 3 Translate の「文脈」の欄に題名や直前の段落を渡すと、こうした誤りが減ることを確かめました。
この方式を、PDF の翻訳に組み込みます。
あわせて、節の見出しの訳の誤りを減らします。
計画のマイルストーン M6 のうち、文脈の扱いに当たります。

## 3. 設計判断

### 文脈に入れるもの

翻訳単位の種類ごとに、次のものを入れます。

| 種類 | 文脈に入れるもの |
| --- | --- |
| 本文 | 論文の題名、節の見出し、直前の本文の段落。文の途中で終わる段落には、直後の本文も入れる |
| 節の見出し | 論文の題名、その節の最初の本文の段落 |
| 要旨、図表の説明文、脚注 | 論文の題名 |
| 題名 | なし |

- 書式は、実験の `labeled` と同じです。1 行に 1 項目で、英語のラベル(`Title:`、`Section:`、`Previous paragraph:`、`Following text:`)を付けます。
- 文脈の中の数式の目印は、「…」に置き換えます。
- 長さの上限は、題名 300 字、節の見出し 200 字、直前の段落 400 字(後ろから)、直後の本文 200 字(前から)です。直前の段落を後ろから取るのは、終わりのほうが今回の段落に近いためです。どちらも、単語の切れ目で切ります。
- 図表の説明文と脚注に、直前の本文を入れない理由は、読む順で直前にある本文が、その説明文や脚注と関係があるとは限らないためです。

### 直前の段落と節の見出しを探す範囲

- 節の見出しと直前の段落は、そのページと前のページの 2 ページの範囲で探します。見出しをはさむと、直前の段落は引き継ぎません。
- 2 ページより前にさかのぼらない理由は、どのページから翻訳を始めても、同じ文脈になるようにするためです。訳文の保存の鍵は、文脈を含む依頼の文字列から計算します。さかのぼる範囲が、準備が済んでいるページによって変わると、翻訳を始めるページによって鍵が変わり、保存した訳文が使われなくなります。
- そのため、2 ページ以上にわたって見出しが無い節では、3 ページ目以降の段落に、節の見出しが入りません。
- 題名は、1 ページ目の題名(レイアウト検出の種類が `doc_title` の段落)から取ります。すべての依頼に入るので、翻訳を始めるときに、最初に 1 ページ目を準備します。題名が見つからない場合は、題名なしで進めます。

### 文の途中で終わる段落

- 文の終わりの記号で終わらない段落(コロンで終わる段落を含む)には、同じ段の真下にある本文を、直後の本文として文脈に入れます。独立した数式をはさんで文が続く場合に当たります。計画の「前半と後半を別々に訳し、互いを文脈の欄に入れる」に対応します。後半の段落には、直前の段落として、前半が入ります。
- 段やページをまたいでつないだ翻訳単位には、直後の本文を入れません。続きは、すでに原文に含まれているためです。

### 節の見出し

- 見出しの番号("3.2"、"1."、"A." など)は、訳す前に原文から外し、訳文の前にそのまま付けます。番号を付けたまま訳すと、"6 Results" が「6件の結果」のように、番号が個数として訳されることがありました。
- 英字 1 文字の番号は、ピリオドが付いている場合に限って番号とみなします。冠詞の "A" で始まる見出しと区別するためです。
- 見出しの文脈に、その節の最初の段落を入れます。見出しは短く、題名だけでは意味が決まらない語があるためです("Constituency Parsing" が「選挙区解析」と訳されていました)。
- 番号を外したことで、本文の段落の文脈に入る節の見出しも、番号なしの文字列になります。

### 履歴の欄を使わない

理由は、`note/016_probe-context.md` の「決めたこと」に書いたとおりです。

## 4. 動作確認

環境は、macOS 26.6(Apple M5、メモリ 24 GB)、Node.js 26.13.1、Chrome、`npm run dev`、llama.cpp 1.0.0 です。
llama-server は `npm run model -- --port 8081`(モデルは `2b`、Q4_K_M、同時処理数 4)、レイアウト検出は WebGPU です。

- `npm test`: 352 件すべて成功。
- `npm run build`: 成功。

### 翻訳

文脈を付けると依頼の文字列が変わるため、保存してあった訳文は使われず、全体が訳し直されました。

| 論文 | 翻訳単位 | 依頼 | 時間(秒) | 失敗 | 原文のまま残した単位 |
| --- | ---: | ---: | ---: | ---: | ---: |
| arXiv 1512.03385(2 段組) | 132 | 130 | 75.7 | 0 | 0 |
| arXiv 1706.03762(1 段組) | 104 | 103 | 45.2 | 0 | 0 |

- 時間は、「この PDF を翻訳する」を押してから、すべての翻訳単位を訳し終えるまでです。レイアウト検出の時間を含みます。測定は 1 回です。
- この測定は、見出しの番号を外す変更の前に行いました。変更のあとは、依頼の文字列が変わった翻訳単位だけが訳し直されたため、通しでは測り直していません。
- 依頼が翻訳単位より少ないのは、文脈を付けない題名などに、保存した訳文が使われたためです。
- 文脈なしで測った時間(`note/011_pdf-translation.md`、1706.03762 で 47 秒)と比べて、時間は増えていません。
- 開き直して翻訳すると、どちらの論文も、依頼は 0 件でした。

### 文ごとの訳し直し

- 見出しの番号を外したあとで 1512.03385 を訳し直した回(依頼 87 件)に、文ごとの訳し直しが 1 件起き、訳し直しで目印がそろいました。実物で起きたのは、これが初めてです。
- どの段落で起きたかは、確かめていません。この時点では、訳文の箱に印を付けていませんでした。

## 5. 注意点・残課題

- 文脈を付けても、題名、節の見出し、直前の段落から意味が決まらない語は、誤って訳されることがあります(`note/016_probe-context.md` の "net" の例)。
- 段落ごとに独立して訳すため、同じ語の訳語が、段落によって変わることがあります。訳語を固定する手段(PLaMo の用語集の欄)は、まだ使っていません。
- 見出しの先頭の数が、番号ではなく内容の一部である場合(年で始まる見出しなど)も、番号として外されます。訳文の前にそのまま付くので、文字は失われませんが、訳文の語順が不自然になる可能性があります。
- 文脈を付けたことで、入力のトークンが増えます。1 つの依頼の入出力の合計は、llama-server の設定で 2,048 トークンまでです。長い段落では、文脈の分だけ、上限に達しやすくなります。見本の 2 本では、上限に達した訳文はありませんでした。
