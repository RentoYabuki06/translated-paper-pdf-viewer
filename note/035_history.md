# 035 開いた PDF の履歴を保存し、左の一覧から開き直す

## 1. 目的

利用者から、同じ PDF を何度も翻訳し直すのが面倒なので、履歴を保存して、左から選んで再開できないか、という依頼がありました。
訳文は、すでにブラウザに保存しています。
足りなかったのは、PDF のファイルそのものです。ページを開き直すたびに、ファイルを選び直す必要がありました。

| `src/viewer/PdfViewer.tsx` | PDF を開いたときに履歴に入れる。「履歴」のボタンと、左に出す一覧を追加 |

## 3. 設計判断

- サーバーを持たないアプリですが、ブラウザ内蔵のデータベース(IndexedDB)には、ファイルのデータをそのまま置けます。PDF のファイルを、ここに保存します。
- 履歴から選ぶと、ふだんの開く処理をそのまま通ります。翻訳は自動で始まり(`note/033_auto-translate.md`)、保存してある訳文が使われます。訳文そのものを、履歴の側に持つことはしていません。訳文は、依頼の内容から求めた鍵で引けるので、PDF さえあれば、同じ訳文に行き着くためです。
- 保存先は、訳文の保存先とは別のデータベース(`translated-paper-pdf-viewer-history`)にしました。訳文のデータベースに足すには、版を上げる必要があり、開いたままの古い画面があると、版の切り替えが止まります。
- 一覧に出す情報(名前、ページ数、大きさ、時刻)と、PDF のファイルは、別の入れ物に分けました。一覧を作るときに、ファイルを読まずに済みます。
- PDF を見分ける値には、PDF.js がファイルの内容から求める値(fingerprint)を使います。同じ PDF を開き直すと、履歴の行は増えず、時刻だけが新しくなります。
- 上限は 30 件です。超えた分は、最後に開いたのが古いものから消します。論文 1 本は数 MB なので、30 件で 100 MB 前後になります。
- 一覧は、画面の左端に重ねて出し、選ぶと閉じます。常に出したままにはしませんでした。原文と訳文を並べる表示は、画面の幅をすべて使うためです。
- 履歴から消す操作は、確認を出さずに、すぐに消します。消えるのは PDF の複製だけで、訳文は残り、もとのファイルを開けば元に戻るためです。

## 4. 動作確認

環境は、macOS 26.6(Apple M5)、Chrome 157 です。`npm run dev` のページで確かめました。

- `npm test`: 479 件すべて成功。
- `npm run build`: 成功。
- arXiv 1706.03762 を開くと、ボタンが「履歴(1)」になり、一覧に、名前、15 ページ、2.2 MB、時刻が出ました。いま開いている PDF の行に、印が付きました。
- URL に何も付けずに開き直し(PDF を開いていない状態)、一覧から選ぶと、15 ページが開き、5.7 秒で「翻訳が終わりました: 104 / 104 段落」と表示されました。一覧は閉じました。この時間は、レイアウト検出を含みます。
- 一覧の「×」を押すと、ボタンが「履歴(0)」になり、データベースの 2 つの入れ物が、どちらも 0 件になりました。開いているページは、そのまま残りました。
- 確認のあと、もう一度 arXiv 1706.03762 を開いて、履歴に戻しました。

### 未確認

- 上限(30 件)を超えたときに、古いものが消えること(消す対象を選ぶ処理は、テストしています)。
- 翻訳が途中の PDF を、履歴から開いて、残りだけが訳されること。
- 大きな PDF(数十 MB 以上)の保存。
- プライベートウィンドウなど、IndexedDB が使えない場合の表示。
- ブラウザを終了して、開き直したあとの履歴。
- 保存先の処理(IndexedDB の読み書き)に、単体テストはありません。

## 5. 注意点・残課題

- 履歴は、このブラウザの中だけにあります。ブラウザのサイトのデータを消すと、履歴も訳文も消えます。
- 履歴から選んだあとの表示位置(何ページ目を読んでいたか)は、覚えていません。先頭から表示します。
- 履歴から消しても、その PDF の訳文は、訳文の保存先に残ります。訳文を消す手段は、アプリにはありません。
