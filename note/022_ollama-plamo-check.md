# 022 Ollama で PLaMo 3 Translate を動かす確認

## 1. 目的

`note/018_ollama-backend.md` と `note/019_server-settings.md` で、Ollama へ翻訳を依頼する処理と、依頼先を選ぶ画面を足しました。
その時点では、Ollama との通信を別のモデルで確かめただけで、PLaMo 3 Translate を Ollama で動かす確認が残っていました。
README の「今後の予定」の 3 番目に当たります。
この確認を行い、llama-server との違いを README に書きます。

## 2. 変更内容

アプリの動作は変えていません。
変えたのは、説明の文章だけです。

| ファイル | 内容 |
| --- | --- |
| `README.md` | 「Ollama を使う場合」の節を、確かめた結果で書き直した(モデルを Ollama に入れる手順、アプリの設定、llama-server との違い)。「現在の状態」と「今後の予定」を更新し、出典に Ollama の説明書を足した |
| `src/viewer/ServerPanel.tsx` | 「翻訳サーバー」の画面の、Ollama についての説明文を、確かめた内容に合わせた |

## 3. 設計判断

### モデルの入れ方

- llama-server が取得済みのモデルのファイルを、`ollama create` で Ollama に取り込みました。
- 理由は 2 つです。追加のダウンロードが要りません。また、llama-server と同じファイルを使うので、訳文に違いが出た場合に、原因をソフトの違いに絞れます。
- Ollama に、Hugging Face から直接取得させる方法は、試していません。

### アプリの動作は変えない

- Ollama では位置符号化の補正が効かないことが分かりました(`note/021_probe-backends.md`)。それでも、Ollama を選べなくする変更や、翻訳を止める変更は、していません。
- 違いは一部の段落の言い回しで、訳せなくなるわけではありません。llama-server が主な依頼先であることも、これまでどおりです。
- 「翻訳サーバー」の画面の Ollama の欄には、もとから「長い段落で、訳の質が落ちる可能性があります」という説明がありました。これは推測でした。確かめた事実(一部の段落で、訳文が llama-server のものと変わる)に書き換えました。

### 「同時に依頼する数」の既定は 1 のまま

- Ollama は、既定では依頼を 1 件ずつ処理します。同時に 4 件を送っても、時間は変わりませんでした(「同時に送る依頼」)。
- 既定を変える理由が無いので、1 のままにしました。

## 4. 動作確認

環境は、macOS 26.6(Apple M5、メモリ 24 GB)、Node.js 26.13.1、Chrome 157、`npm run dev`、llama.cpp 1.0.0、Ollama 0.40.16 です。
比べる相手の llama-server は、`npm run model -- --port 8081`(モデルは `2b`、Q4_K_M、同時処理数 4)で起動したものです。

- `npm test`: 386 件すべて成功。
- `npm run build`: 成功。
- 「翻訳サーバー」の画面で Ollama を選び、書き換えた 2 つの説明文が表示されることを確かめました。

### モデルの取り込み

README の「モデルを Ollama に入れる」に書いた 2 つのコマンドを、そのまま実行しました。

- `ollama create` は、`success` と表示して終わりました。
- `ollama list` に、`plamo-3-translate-2b`(1.8 GB)が表示されました。
- Ollama の保存場所(`~/.ollama/models/blobs`)に、1,807,203,040 バイトのファイルが作られました。ファイルの名前に含まれるハッシュ値は、llama-server が取得したファイルのものと同じでした。
- 翻訳を依頼したあとの `ollama ps` は、このモデルについて、`100% GPU`、`CONTEXT` が 2048、`RUNNER` が `llamacpp` と表示しました。

### 短い依頼

アプリの依頼の処理(`OllamaBackend` と `LlamaServerBackend`)を Node.js から呼び、同じ依頼 3 件を両方に送りました。
3 件には、数式の目印を含む依頼と、文脈を付けた依頼を含みます。

- 訳文は、3 件とも一字一句同じでした。数式の目印も、同じ位置に残りました。
- 入力のトークン数(32、48、58)と、出力のトークン数(12、25、8)も、3 件とも同じでした。
- 報告された生成の速度は、Ollama が 68 から 73 トークン毎秒、llama-server が 61 から 69 トークン毎秒でした。

`note/018_ollama-backend.md` では、Ollama が文頭の印(`<|plamo:bos|>`)を付けるかどうかを、未確認としていました。
入力のトークン数が llama-server と同じで、訳文も同じだったので、Ollama は llama-server と同じ入力を処理していると判断しています。
文頭の印そのものを、直接には確かめていません。

### 長い入力

入力の長さを変えた比較は、`note/021_probe-backends.md` に書きました。
結果は次のとおりです。

- Ollama の訳文は、長さの違う 4 通りの入力すべてで、位置符号化の補正を付けない llama-server の訳文と、一字一句同じでした。
- `npm run model` の llama-server(補正あり)とは、短い 2 通りで同じ、長い 2 通りで違う訳文になりました。

### 停止文字列を指定しない依頼

`note/018_ollama-backend.md` では、訳文の終わりの印を停止文字列に指定する必要があるかどうかを、未確認としていました。

- 停止文字列を指定しない依頼を 1 件送ると、Ollama は、訳文だけを返して、自分から生成を止めました(`done_reason` は `"stop"`、出力は 15 トークン)。
- 停止文字列を指定した依頼と、同じ訳文でした。
- 停止文字列の指定は、印が文字として出てきた場合の備えとして、そのまま残します。

### 同時に送る依頼

段落 8 件(出力は合計 697 トークン)を、同時に送る数を変えて、Node.js から Ollama に送りました。

| 同時に送る数 | 時間(秒) | 全体の速度(トークン毎秒) |
| ---: | ---: | ---: |
| 1 | 11.4 | 61 |
| 2 | 10.9 | 64 |
| 4 | 10.9 | 64 |

- 同時に送っても、時間は変わりませんでした。Ollama の説明書は、1 つのモデルが同時に処理する依頼の数(`OLLAMA_NUM_PARALLEL`)の既定を、1 としています。
- どの場合も、8 件すべてが成功し、訳文は、1 件ずつ送った場合と同じでした。
- Ollama の側の設定を変えて、同時に処理する数を増やすことは、試していません。

### ブラウザでの確認

「翻訳サーバー」の画面で Ollama を選び、モデルの名前に `plamo-3-translate-2b` を入れて確かめました。

- **接続の確認**: 「接続できました」と表示され、モデルは `plamo-3-translate-2b`、同時に処理できる依頼は 1 件、1 件の依頼で使える長さは 2048 トークンと表示されました。注意は表示されませんでした。モデルの名前の候補には、Ollama に入っている 3 件が出ました。
- **同時に依頼する数**: 4 に変えて「接続を確かめる」を押すと、同時に処理できる依頼が 4 件と表示されました。
- **貼り付けた英文の翻訳**: 2 段落を訳し、どちらも完了しました(1.3 秒、73 トークン)。
- **PDF の翻訳**: 次の表のとおりです。

| 論文 | 同時に依頼する数 | 翻訳単位 | うち、つないだもの | 依頼 | 時間(秒) | 失敗 | 途中で切れた訳文 | 原文のまま残した単位 | 収まらなかった訳文 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| arXiv 1706.03762(1 段組) | 1 | 104 | 5 | 104 | 107.6 | 0 | 0 | 0 | 0 |
| arXiv 1512.03385(2 段組) | 4 | 132 | 14 | 132 | 192.2 | 0 | 0 | 0 | 0 |

- 時間は、「この PDF を翻訳する」を押してから、すべての翻訳単位を訳し終えるまでです。レイアウト検出の時間を含みます。測定はそれぞれ 1 回です。
- llama-server(同時処理数 4)で測った時間は、1706.03762 で 45.2 秒、1512.03385 で 75.7 秒でした(`note/017_translation-context.md`)。Ollama での時間は、その 2.4 倍と 2.5 倍です。llama-server の値は以前の測定のもので、依頼の数が少し違います(103 件と 130 件)。
- 文ごとの訳し直しは、どちらの論文でも起きませんでした。
- llama-server で保存してあった訳文は、使われませんでした。保存した訳文が、モデルの名前ごとに分かれるためです。
- 1706.03762 を開き直して翻訳すると、依頼は 0 件で、104 件すべてに保存した訳文が使われました。
- 1512.03385 の 2 ページ目を目で見て、2 段組のそれぞれの段落の位置に訳文が重なり、文中の数式が訳文の中に入っていることを確かめました。

### 実際の論文での訳文の違い

arXiv 1706.03762 の訳文を、Ollama と llama-server(補正あり)で、翻訳単位ごとに比べました。
ブラウザに表示された訳文を、翻訳単位ごとに取り出して比べています。
llama-server の訳文は、保存してあったものです。

- 104 件のうち、99 件は一字一句同じでした。
- 5 件は、訳文が違いました。違いが始まる箇所は、たとえば次のとおりです(前が Ollama、後ろが llama-server)。
  - 「マスキング」と「マスキング処理」
  - 「英語-フランス語翻訳」と「英仏翻訳」
  - 「目的事項」と「目的」
- 違った 5 件の訳文の長さは、およそ 50 文字から 310 文字でした。短い訳文の翻訳単位でも、違いが出ています。依頼には文脈(題名、節の見出し、直前の段落)が付くので、入力は、訳す段落より長くなります。
- この 5 件の Ollama の訳文が、補正なしの llama-server の訳文と一致するかどうかは、確かめていません。
- どちらの訳文が良いかは、評価していません。

### 確認の途中で起きたこと

- 確認の途中で、開発に使っているパソコンが、ふたを閉じられてスリープに入りました。復帰のときにブラウザのページが読み込み直され、表示していた訳文が消えました。訳文は保存されていたので、開き直して比較を続けました。上の表の時間は、スリープの前に測り終えたものです。
- 長い入力の比較を最初に行ったとき、llama-server の速度が 3 トークン毎秒と報告された依頼が、1 件ありました。この依頼の結果は、パソコンのスリープ(185 秒)からの復帰の 9 秒後に返っていて、依頼の途中にスリープが入っていました。測り直した値は 68 トークン毎秒でした。この記録と `note/021_probe-backends.md` の数値は、測り直したあとのものです。

### 未確認

- Ollama の側で、同時に処理する数(`OLLAMA_NUM_PARALLEL`)を増やした場合の動作と速度。
- `2b`・Q4_K_M 以外のモデルと、0.40.16 以外の版の Ollama。
- Ollama に、Hugging Face からモデルを直接取得させる方法。
- 取り込んだモデルを `ollama rm` で消す操作。README には、Ollama の説明書に載っているコマンドを書きました。
- Ollama での訳文の質の評価。

## 5. 注意点・残課題

- **Ollama では、位置符号化の補正が効きません。** 一部の段落で、訳文が llama-server のものと変わります。補正の値を Ollama に渡す手段は、見つかっていません。補正は、PFN の公式の道具(plamo-translate-cli)が llama-server に渡しているものなので、llama-server を主な依頼先とする方針は変えません。
- **Ollama は、既定では依頼を 1 件ずつ処理します。** PDF の翻訳には、同時に 4 件を処理する llama-server の 2.4 倍から 2.5 倍の時間がかかりました。
- **モデルの読み込みが入る依頼は、遅くなります。** 読み込みが入った依頼は、そうでない依頼より、2 秒から 7 秒ほど長くかかりました(観察は 2 回)。Ollama の説明書によると、既定では、モデルはメモリに 5 分間保たれたあとで降ろされます。
- 開発に使っているパソコンの Ollama には、確認に使ったモデル(`plamo-3-translate-2b`、1.8 GB)を残してあります。
- ブラウザの設定は、確認のあとで、もとの依頼先(llama-server、`http://127.0.0.1:8081`)に戻しました。Ollama で訳した 2 本の論文の訳文は、ブラウザに保存されたままです。
- 確認に使ったスクリプトのうち、訳文の比較は、`npm run probe:backends` として残しました(`note/021_probe-backends.md`)。同時に送る依頼と、停止文字列を指定しない依頼のスクリプトは、リポジトリに入れていません。どちらも、アプリの依頼の処理、または Ollama の `/api/generate` を、Node.js から呼ぶだけのものです。
